# OpenArtShow — 웹 3D 가상 전시 플랫폼

OpenArtShow는 **웹 브라우저만으로 접속하는 3D 가상 전시 플랫폼**입니다. 작가는 손쉽게 전시를 등록하고, 관람객은 루이지애나 미술관 스타일의 몰입감 있는 3D 전시장에서 작품을 감상할 수 있습니다.

## 주요 기능

- **3D 전시 감상**: 아치형 목조 볼트 천장, 통유리 벽, 중정의 큰 나무가 있는 실내 공간
  - PC: WASD 이동, Shift 달리기, 마우스 시점 조작
  - 모바일: 왼쪽 화면 터치 이동 + 오른쪽 화면 드래그 시점
- **작품 정보**: 작품 3m 이내 접근 시 우측에 정보 패널 표시
- **라이트박스**: E키로 작품 전체화면 확대 (ESC/X/배경클릭 닫기)
- **멀티플레이어**: 같은 전시장에 접속한 사람들이 아바타로 표시되고, Enter키로 채팅 가능
- **사운드**: 입장 시 새소리·바람 앰비언트 음향
- **전시 선택**: 로비의 전시 목록 또는 URL 파라미터(`?g=<전시id>`)로 전시 선택
- **아야모(Ayamo)**: 자체 제작 마스코트 캐릭터 — 헤어·표정·의상 꾸미기 (저장됨). 콕 찌르면 "아얏!" 하는 리액션에서 이름이 왔다
- **방명록·도슨트 투어·사진 촬영**: G키 방명록, T키 자동 투어, P키 SNS용 캡처
- **시간 연동 테마**: 접속 시각에 따라 아침/낮/석양/밤 조명 자동 전환

## 배치 에디터 (개발용 · behind-flag)

three.js 공식 editor 를 반입해 개조한 것이다. **어디에도 링크하지 않는 개발 전용 도구**이고
라이브 승격은 감독·팀장 게이트다 — 그래서 **여기에 URL 을 적지 않는다.**

목적은 감독 요구(*"월드2를 내가 직접 배치·튜닝. glb파일을 내가 직접 넣고"*)의 1단계다.
GLB 를 불러와 보고 다듬는 자리이고, **배치 결과를 world2 로 보내는 경로는 아직 없다.**

### 여는 법 (로컬)

```bash
npx vite build && npx vite preview      # 또는 npm run dev
# 브라우저에서 /app/editor.html
```

### 되는 것

- **GLB 불러오기** — `File ▸ Import`. 드래그드롭도 된다.
- **씬 조작** — 이동·회전·크기(gizmo), 계층 트리, 재질·지오메트리 속성 편집.
- **환경광이 기본으로 켜져 있다** — `ModelViewer`(three 내장 `RoomEnvironment`)를 부팅 시 자동
  적용한다. 원본 editor 는 `None` 으로 시작해 PBR 재질이 **검게** 보였다(감독 신고 결함).
  **직접 `None` 을 고르면 그 선택을 존중하고 다시 덮지 않는다.**
- **프로젝트 저장·복원** — 브라우저(IndexedDB) 자동저장. 새로고침해도 작업이 남는다.
- **내보내기** — GLB / DRACO / OBJ / STL 등 원본 editor 기능 그대로.

### 안 되는 것 (경계)

- **이 도구에서 world2 로 배치를 보내는 경로는 없다.** 오픈월드 배치는 editor 가 아니라
  **world2 안에서** 한다(아래 절) — editor 는 WebGL, world2 는 WebGPU 라 룩이 달라서,
  world2 안에서 놓으면 보는 화면이 곧 배포 화면이 되기 때문이다(팀장 판정 2026-08-09).
- **작업물이 이 브라우저에만 있다.** 다른 기기·다른 사람에게 안 보인다. 공유하려면 GLB/JSON 으로
  내보내 저장소에 커밋해야 한다(무저장·자기완결 설계의 귀결).
- **반입하며 걷어낸 기능**: Pathtracer 렌더, Video 탭, 스크립트 탭, 지오메트리 Modifier,
  KTX2·VRML 로더, XR 컨트롤러 모델. 전부 외부 CDN·wasm 의존이라 자기완결에 걸린다.
- 크로미움/웹킷 기준으로만 확인했다. 그 밖의 브라우저는 **안 쟀다.**

### 알려진 문제

- 부팅마다 환경맵 렌더타깃이 회수 없이 남는다(**태스크 #32**). 화면에는 안 보이고 editor 사용자만
  해당된다. 오래 켜 두고 새로고침을 반복하면 메모리가 는다.
- 자동 검사가 이 도구의 **부팅 경로 하나만** 실행한다 — 저장 상태 복원·`File ▸ New` 이후 밝기는
  사람이 확인한 것이 유일한 근거다(**태스크 #35**).

반입 경위와 실패 기록은 [docs/DEVLOG.md](./docs/DEVLOG.md)·[docs/BOARD.md](./docs/BOARD.md)에 있다 —
여기에 복제하지 않는다.

## 오픈월드 배치 편집 (world2 · behind-flag)

감독 요구 *"월드2를 내가 직접 배치. 튜닝할수있는 편집 툴가능? glb파일을 내가 직접 넣고"* 의
본체다. `world2.html?edit=1` 로 켜지고, **`?edit=1` 없는 세션은 편집 코드를 내려받지도
않는다**(동적 import).

### 되는 것

- **주행이 기본이다.** 링크를 열면 평소처럼 걸어다닌다 — 마우스 시점·WASD·터치 조이스틱
  전부 라이브와 같다. 편집은 **오른쪽 위 「✏️ 편집」 버튼**(또는 `Tab`)으로 켠다.
  편집 중에만 포인터락을 놓아 커서를 살리고, 시점은 **마우스 오른쪽 버튼 드래그**로 돈다.
  ⚠ 처음엔 `?edit=1` 이 곧 편집 상시 켜짐이었고 그것이 **주행을 통째로 막았다**(감독 신고
  2026-08-12). 지금은 편집 리스너가 편집 모드에서만 붙는다 — 조건문이 아니라 붙였다 떼는
  구조라 주행 영향이 **구조적으로 0** 이다.
- **놓기** — 팔레트에서 고른 뒤 지면 클릭, 또는 **GLB 를 화면에 끌어다 놓기**.
  놓인 물건은 그 자리에서 밟는 바닥 높이에 얹힌다(잔디 0.07 · 도로 0.14 · 광장 0).
- **다루기** — 좌드래그 이동 · 우드래그 시점 · `Q`/`E` 회전 · `R`/`F` 크기 · `Z`/`X` 높이 ·
  `Del` 삭제 · 복제 · 격자 0.5m 스냅 토글. 선택한 것은 바닥 링으로 표시된다.
- **내보내기** — `JSON 내보내기` 로 `world2-overlay.json` 다운로드. 손실이 있으면
  **1차 클릭에서는 저장하지 않고** 문제 항목을 화면에서 골라 사유를 띄운다.
- **배포** — 그 JSON 을 `frontend/assets/world2-overlay.json` 에 커밋하면 라이브에 붙는다.
  마을 기본 배치는 그대로 계산되고 사용자 배치만 **가산 레이어**로 얹힌다.

### 마을이 생기는 규칙도 돌린다

노브 바(우측 하단 「개발자 옵션」)에 슬라이더 셋과 버튼이 있다.

- **건물**(`?bld=`) · **나무**(`?tree=`) · **전체**(`?density=`) — 각각 1~8배.
  전체는 건물·나무를 함께 올린다(부하 시험용 기존 노브).
- **[마을 적용 (새로고침)]** — 슬라이더는 주소만 바꾸고 이 버튼이 실제로 반영한다.
  슬롯 풀이 부팅 1회에 봉인되기 때문이다(개수 불변식). 값이 그대로면 새로고침하지 않고
  「지금 값 그대로」라고 답한다.
- 곱 결과는 기존 노브의 최대치(`maxBuildings 32`·`maxTrees 64`)에서 잘린다 — 그 이상은
  스모크·게이트가 돌아 본 적이 없다. 축을 가르는 것과 범위를 넓히는 것은 다른 일이다.

⚠ **2026-08-12 이전에는 이 노브가 겹친 마을을 만들었다.** 건물이 사분면 넷에 1:1로
배정되는데 5채째부터 `undefined` 사분면이 조용히 0으로 폴백해 이미 건물이 선 자리에
겹쳤다(`density=2` 에서 3,192쌍, 최대 4.27m). 지금은 사분면이 동나면 빈 자리를 찾고,
없으면 그 채를 놓지 않는다 — 밀도를 올리면 채수가 상한이 아니라 **파셀이 감당하는
만큼**에서 포화한다.

### 안 되는 것 (경계)

- **끌어다 놓은 GLB 는 그 세션에서만 보인다.** 브라우저 임시 주소라 내보낸 JSON 에는
  **파일명만** 남는다 — 그 GLB 파일도 함께 주셔야 배포에 붙는다. 화면이 그 사실을 경고한다.
- **마을 파츠 자체(집·나무·가로등)의 개별 위치는 편집 대상이 아니다.** 규칙으로 수를
  조절할 뿐 하나를 집어 옮기지는 못한다 — 좌표 결정론 불변식과 부딪히는 별개 축이라
  계약 v2 가 필요하다.
- **고밀도의 프레임 시간은 안 쟀다.** 겹침과 개수 불변식만 확인했다.
- 파일 이름은 영문·숫자·`_ - .` 만, 확장자는 소문자 `.glb`. 그 밖은 커밋 가능한 경로가
  아니라서 거부한다.

### 검증 상태

`npm run gate` 6종 + `tests/world2-overlay*.test.ts` + CI `verify`·`smoke`.
로컬 실측(2026-08-12): 기본 세션 4xx 0 · 콘솔 에러 0, `?edit=1` 콘솔 에러 0 ·
클릭 배치 성공 · 포인터락 미발생. **실기기(WebGPU) 확인은 감독 몫이다** — 헤드리스는
WebGL 이라 렌더 경로가 다르다.

## 폴더 구조

> 아래는 **개요**다. `frontend/js/`의 실제 모듈은 이후 SOLID 분해로 다수의 하위 모듈로
> 나뉘었고(예: `scene.js`·`ui.js`·`space-render.js`는 얇은 재수출 배럴), 소스는 TypeScript(`.ts`)로
> 점진 전환 중이다. **현행 모듈 지도·아키텍처 원칙은 [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md)가 SSOT.**

```
openartshow/
├── frontend/                   # 프론트엔드 소스
│   ├── index.html              # 3D 전시장 (app/로 배포)
│   ├── landing.html            # 랜딩 페이지 (루트의 index.html로 배포)
│   ├── guide.html              # 이용 안내 (루트의 guide.html로 배포)
│   ├── studio.html             # 작가 스튜디오 (app/로 배포)
│   ├── js/                     # 프런트엔드 모듈 (.ts 소스 + 컴파일 .js)
│   │   ├── main.js             # 메인 진입점(Composition Root) 및 전시장 초기화
│   │   ├── player.js           # 플레이어 이동 및 카메라 제어
│   │   ├── artworks.js         # 작품 로딩 및 정보 패널
│   │   ├── config.js           # 전역 설정 상수
│   │   ├── space.ts            # 공간 문서 스키마 SSOT (normalizeSpace/migrateSpace)
│   │   ├── space-parts.ts      # 파츠 지오메트리·재질 (partGeo/partAccent/MATS)
│   │   ├── multiplayer.js      # PeerJS 기반 멀티플레이어 (P2P 연결, 채팅)
│   │   └── …                   # 그 외 다수 (전체 지도는 docs/ARCHITECTURE.md)
│   ├── galleries/              # 전시 갤러리 데이터
│   │   └── index.json          # 등록된 전시 목록 및 메타데이터
│   ├── assets/                 # 자산 (이미지, 리소스)
│   └── vendor/                 # 외부 라이브러리 (Three.js 등)
└── README.md                   # 이 파일
```

### 배포 구조

- 개발 저장소의 `frontend/landing.html`, `frontend/guide.html` → 루트(`index.html`, `guide.html`)로 배포
- `frontend/index.html`, `frontend/studio.html` → `app/`로 배포
- **자동배포**: `main`에 push하면 GitHub Actions(`.github/workflows/deploy.yml`)가 빌드 후
  `gh-pages` 브랜치로 배포 → GitHub Pages 자동 갱신 (수동 조작 불필요)

## 새 전시 열기

### 방법 A — 공유 링크 발행 (권장, 서버·가입 불필요)
1. https://syhongart.github.io/openartshow/app/studio.html 접속
2. 전시 제목·설명·작품(이미지 URL, 최대 14점 + 대표작 2점) 입력
3. **[공유 링크 만들기]** → 전시 데이터가 압축되어 URL(#gz=)에 통째로 담긴 링크 생성
4. 그 링크를 SNS/메신저에 공유 — 받는 사람은 클릭 즉시 그 전시에 입장
   (같은 링크로 들어온 사람끼리 같은 멀티플레이 방에서 만난다)

### 방법 B — 저장소 상설 등록 (전시 디렉터리에 노출)
1. 스튜디오에서 **[JSON 다운로드]**
2. 파일을 `frontend/galleries/`에 추가하고 `frontend/galleries/index.json`에 메타데이터 등록
3. `main`에 커밋·push → 자동배포(위 "배포 구조" 참조)
