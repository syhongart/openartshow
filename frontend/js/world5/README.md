## 왜 world2 를 포크했나 — world3 가 아니라

world3(포근마을)에는 이미 팔레트 SSOT 가 있어 색 교체가 파일 하나로 끝난다.
그럼에도 world2 에서 출발한 이유는 **지오메트리**다:

- world5 가 쓰는 것: 도로망·빌딩(높이 4~20m)·타워·가로등·파셀 스트리밍 — world2 가
  도시를 전제로 만든 것들이고, world3 에서는 마을에 맞추느라 **낮추고 둥글려야 했던**
  바로 그 자산이다.
- world3 에서 왔다면 버릴 것: 오두막·꽃밭·3단 캐노피 나무·관목 화분. 마을에서 도시로
  가는 것은 거꾸로 가는 셈이다.

팔레트 SSOT 는 **파일을 복사해 왔다**(`parts/palette.ts`). 팀장 조건 1 —
*"착수 첫 커밋으로 이식한다. 리터럴이 쌓인 뒤에는 도입 비용이 급증한다."*

## `world4` 는 결번이다

감독이 명시적으로 "월드5" 라고 지시했다. 팀장 판정: *"명시 발화에 정정을 되묻는 것은
이미 답이 있는 질문이고, 그 왕복이 감독 시간을 쓴다."*

기능상 문제는 없다 — GS-4(`tests/verification-tier.test.ts`)가 `/^world\d+$/` 로
판정하므로 결번과 무관하게 자동 편입된다. `tests/verification-tier.test.ts` 에
`world5` 를 명시적으로 확인하는 단언을 두어 **숫자가 건너뛰어도 잡히는지**를 함께
못 박았다.

## 동기화 정책 — **no-sync 가 기본**

world2 의 후속 개선은 자동 반영하지 않는다. 정기 동기화 의무도 두지 않는다.
필요한 개선이 생기면 **개별 체리픽**하고 아래 표에 적는다.

**world3 와도 no-sync 다.** 두 포크는 서로를 모른다 — `tests/world5-independence.test.ts`
가 world2 참조 0 을 강제하고, world3 참조 역시 트리 밖이므로 같은 검사에 걸린다.

## 무엇이 격리를 지키는가 — 산문이 아니라 검사다

`tests/world5-independence.test.ts` 가 **world5 코드에서 다음의 import 0** 을 강제한다:

- `frontend/js/world2/**` (및 트리 밖 전부 — 어댑터·공용만 예외)
- `frontend/js/sky.js`(원본 — world5 는 자기 포크 `world5/sky.js` 를 쓴다)
- 라이브 보호 4파일(`main.js`·`player.js`·`artworks.js`·`config.js`)

**역방향도 검사한다**(world2 → world5). 한 방향만 막으면 world5 를 갈아엎을 때
world2 가 함께 죽는 경로가 남는다.

진입점(`frontend/js/world5-boot.ts`)과 `world5.html` 의 `<script src>` 도 표본에
들어 있다 — world3 회차에서 **그 둘이 빠져 있어 격리의 첫 관문에 검사가 0이었던**
블로커가 났다(검수관 B2). 같은 구멍을 물려받지 않도록 처음부터 포함한다.

## 포크와 **함께 오지 않은 게이트** — 승격 전에 채울 목록

테스트는 `tests/` 에 있고 `world2/**` 를 import 하므로 **포크를 따라오지 않는다.**
주장(주석)만 따라온다.
