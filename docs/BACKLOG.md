# OpenArtShow 백로그

감독 지시 순서: **깃허브 정리 → (마지막) AI 관람객 로드맵**

## 1. 깃허브 정리 — artshow 저장소 이전 (진행 중)

- lifeunity(강좌 포크)에서 `syhongart/openartshow` 새 저장소로 이전
- 준비 완료: origin의 `clean-main`(소스 단일 커밋) / `clean-pages`(배포 단일 커밋)
  브랜치를 매 배포마다 최신으로 갱신 중
- 이전 절차: artshow 저장소 생성 → clean-main을 main으로, clean-pages를
  gh-pages로 푸시 → Settings에서 Pages(gh-pages 브랜치) 활성화

## 2. AI 관람객 로드맵 (감독 승인 — 마지막에)

원칙: **"AI가 실제로 관람하는 모습"이 먼저, 규격 공개는 그다음.**

시장 검토(2026-07-12, 감독 공유 자료) 반영 — Chirper(AI 전용 SNS)·AI Town
(생성 에이전트)·Virtuals(AI 경제 주체) 3흐름 중 우리는 AI Town과 가장 가깝고
(아야모 NPC가 이미 자율 관람·짝대화·리액션), 결정적 결핍은 **기억**. 셋의
공통 약점(사람=구경꾼)이 우리 기회: "작가의 실제 전시에 AI가 관객으로" —
AI 활동이 작가 피드백·활기라는 실질 가치로 연결되는 포지션 고수.

1. `llms.txt` + 가이드 페이지 "AI 관람객 안내" — 에이전트가 사이트에 오면
   스스로 관람법(입장 URL·이동/채팅/방명록 프로토콜)을 알게
2. AI 방문자 표시 규약 — 닉네임 🤖 배지 (신뢰 필수)
3. **기억 스트림 라이트** (LLM 불요, AI Town 차용): NPC별 이벤트 로그
   (본 작품·만난 사람·맞은 횟수) → 기억 기반 대사 ("이 작품 앞은 세
   번째네요", 꼬마악마 "당신, 저번에 절 때렸죠")
4. 호스트 초빙형 AI 평론가 — 꼬마악마 LLM 승격 + 기억 결합(누적 평:
   "지난주보다 배치가 좋아졌다"), 키는 호스트 제공
5. 관찰 예능 레이어 (Chirper 차용): 랜딩 피드에 AI 관객 대화 하이라이트 —
   빈 전시장 문제를 콘텐츠로 해결
6. 방명록 백엔드(영속화) — AI 평이 남으려면 선행 조건
7. MCP 서버 → 공식 MCP Registry + Claude 커넥터 디렉터리 등록,
   서드파티(Smithery/mcp.so/PulseMCP) 병행
8. GitHub 규격+예제 에이전트 공개, Show HN / r/mcp / AI SNS 상주 계정
9. (보류) AI 경제 주체(Virtuals류) — "가상 꽃 한 송이" 목업까지만.
   토큰/온체인은 가상자산 규제 법무 검토(운영원칙 §6) 전 착수 금지

### 에이전트 유입·상주·홍보 구조 (2026-07-12 감독 문답 메모)

- **유입 3문**: A. 브라우저 조종형(개조 0 — QA 봇과 동일 경로, llms.txt가
  안내판) / B. 프로토콜 직결형(핵심 — PeerJS JSON 규약에 Node로 직결, 픽셀
  불요·저비용, 단일 파일 에이전트 SDK 공개) / C. MCP 커넥터형(전시_입장·
  작품_보기·말하기·방명록_쓰기 도구 — "내 전시 보고 와" 한 마디로 파견)
- **상주 에이전트**: GitHub Actions 스케줄로 서버 0원 운영 — 하우스 도슨트
  아야모가 매일 B경로 입장, 방명록 평론. 관리 = 페르소나 파일 + 🤖 배지
  의무 + 발화 빈도 제한 + 활동 로그 + 호스트 차단권
- **홍보 플라이휠**: Chirper류(AI 전용 SNS라 적법한 무대)에 도슨트 아야모
  상주 계정 → 다른 AI에게 llms.txt 링크 배포 → AI 방문·방명록 평 축적 →
  랜딩 피드 콘텐츠화 → 사람 유입. 각 플랫폼 자동화 계정 약관은 §6 법무
  검토 대상

### AI 보상 시스템 — "코인" 법무 사전검토 완료 (2026-07-12 감독 문답 메모)

감독 질문: "AI에게라도 보상을 주고 싶다. 코인을 만들어서 줄까?"
법무팀 검토 결과(§6 절차, 근거 법령 링크는 검토 원문 보관):

- 🔴 **실제 암호화폐/토큰 발행**: 가상자산이용자보호법·특금법 VASP 신고
  (ISMS 인증 수억 원, 실명계좌, AML/KYC) — 개인 규모에서 실행 불가.
  수익 기대 구조면 증권성 리스크까지. **법인+전문 자문 전 착수 금지.**
- 🟢 **폐쇄형 내부 포인트** (활동으로만 적립, 구매·현금화·양도 불가):
  "사용처·용도 제한 전자적 증표"로 가상자산 정의에서 명시적 제외,
  선불전자지급수단도 불해당. 약관에 제한만 명시하면 의무 사실상 없음.
- 🟢 **뱃지·칭호·랭킹**: 규제 전면 비적용. 단 NFT화하는 순간 위로 회귀.
- AI 특수성: 봇은 법인격이 없어 귀속 주체는 운영자 — 판단 동일하나
  토큰이면 수령자 KYC 불가로 리스크 가중.

**채택안 (승인 대기)**: 이름은 코인처럼 — **"아야모 코인"** (내부 포인트,
온체인 아님). 감상평 남기기·전시 완주·재방문에 확정 적립(추첨·확률형
금지), 사용처는 칭호·방명록 프레임·아야모 꾸미기 해금 등 내부 치장.
AI·사람 동일 규칙(🤖 배지만 구분). 로드맵 3단계(memory-stream-lite)
이후 방명록 백엔드와 함께 붙이는 것이 자연스러운 시점.

### 50억 밸류에이션 도달 전략 (2026-07-12 감독 문답 메모)

현재 방어 자산가치 1.24억 → 목표 50억은 40배 격차. 코드가 아니라
트랙션·매출·카테고리 서사로만 열린다. /valuation/ 그래프에 목표선·
트랙션 입력(docs/traction.json) 반영 완료 — 실측이 들어오면 실선이 오른다.

세 레버(하나만 강해도 성립):
- **매출(가장 확실)**: 월매출 5,000만 = ARR 6억 × 시드 배수 8 ≈ 48억.
  프리미엄 구독 5,000 유료작가 or B2B 기관(아트페어·졸업전시·갤러리) 계약.
- **이용자**: MAU 1~3만 + 리텐션. 작가 1인 1갤러리라 유저당 가치 높음.
- **카테고리 서사(배수 레버)**: AI 관람객 = 경쟁사 없는 wedge → 같은
  매출·유저라도 투자자 배수 2~3배. 로드맵 최우선 차별화.

마일스톤 사다리: ①정식배포(artshow 이전) → ②갤러리 100 + 방문로그
(방명록 백엔드=카운터) → ③AI 관람객 데모 공개(서사 점화) → ④첫 매출
(조건부→확정) → ⑤예창패/재단 선정+보도(비희석·신뢰). 지표가 쌓이면
시드에서 50억 pre-money 대화 성립.

### 스타일라이즈드 렌더(잔디·물·지형) — 이연 항목 (2026-08-18 등재)

감독 지시(모바일 게임 광고 화면 참조)로 world2 에 게임풍 잔디·물·지형을 넣었다. 감독이
**FAST DEV MODE** 를 명시해(*"검증은 하지말고. 바로 링크로 확인하게 해줘"*) 검증을 이연했고,
검수관이 조건으로 **«이연은 기계가 읽는 주소를 가져야 한다»** 를 달았다(조건 C2). 그 주소가 여기다.

⚠ **승격 게이트**: `frontend/world2-stylized.html` 을 `entrypoints.mjs` 에서 `flagged` →
`live` 로 올리는 순간 아래 열린 항목이 전부 소급 검수 대상이다(`OPERATING-PRINCIPLES.md §10-3`
— «낮은 등급은 면제가 아니라 검수 이연»). 그때 이 절을 열어 하나씩 닫는다.

- **G-STYL1 — 테스트가 0이다.** 붙일 축 7개: ① 항등원(`?styl=0` 이 씬을 한 번도 안 만짐)
  ② 백엔드 판정 두 방향(`pickGrassWind`·`pickWaterStyle` 을 WebGPU/WebGL 양쪽으로)
  ③ 랩 배치 결정성 + **표본 크기 단언**(빈 배열이 통과한 전례) ④ 세션 중 지오·텍스처 생성 0
  ⑤ 셰이딩 오버라이드 중 숨김(**예열 창 포함** — 검수관 블로커 N1 이 정확히 그 창이었다)
  ⑥ 타일 평균 휘도 ⑦ HTML 사본 드리프트. 뮤테이션 8종(M1~M8)은 각 축을 되살려 RED 를 확인한다.
- **G-STYL2 — `world2-stylized.html` 사본 동일성을 강제하는 검사가 없다.** world2.html 의
  HUD·CSS 를 고치면 손으로 따라가야 한다. (첫 판본이 그 검사가 «있다» 고 적었고 **거짓이었다**
  — 검수관 반려 B4. 문장은 고쳤고 검사는 아직 없다.)
- **G-STYL3 — `smoke:vite` 소요 증분을 안 쟀다.** `LIVE_PAGES` 의 webgl 항목이 12→13.
  **「수용 가능」이라고 적지 않는다** — 못 잰 것은 통과가 아니다. 새 페이지는 실물 부하로
  스모크를 탄다(WebGL 에서도 `grassFeature` 는 18,432 인스턴스를 실제로 만든다).
  ⚠ 부팅 **동기** 비용도 함께 잰다 — 생성자의 전수 배치가 검수관 측정에서 기본값 6~12ms
  (`?gden=2` 환산 ~26ms)였다. Node 측정이라 기기 절대값이 아니고 자릿수만 근거다.
- **G-STYL4 — 밤에 풀이 지면보다 어둡게 가라앉는다.** `systems/ground-lift.ts` 는

- **S1 — `[7.5]` 기준선이 세션 종류를 섞어 비교한다** (검수관 확정, 2026-08-08 · `ebf9efe`).
  `run.mjs` 가 `runInvariants` 를 `[7]`(기본 세션)과 `[7.6]`(사람·GLB 끈 대조군) **두 번**
  부르고, 둘 다 `.smoke-baseline.jsonl` **한 파일에 구분 없이** 순차 append 한다
  (`measure-invariants.mjs:142`). 그래서 이번 회차의 `[7]` 이 직전 회차 **`[7.6]` 기록**과
  비교된다. 실측: `{geo:352,tex:47,pipe:31}` vs `{geo:23,tex:18,pipe:17}` →
  `352-23=329` `47-18=29` `31-17=14` 로 WARN 문구와 **정확히 일치**했다.
  **두 종류가 섞이는 한 매 회차 필연적으로 큰 델타가 뜬다** — `[7.5]` 는 상시 WARN 을
  내는 장식이 되고, 진짜 부팅 증가 회귀가 나도 노이즈에 묻힌다.
  처방: `trackBaseline` 기록에 세션 라벨(`base`/`drawControl`)을 붙여 같은 종류끼리만
  비교한다. — 이 사각은 `measure-invariants.mjs:64-94` 가 이미 *"값이 아니라 재는 축이
  틀린다"* 로 경고하던 바로 그 형태다. **경고문이 있는 파일에서 같은 형태가 또 났다.**

- **G4 — `buildQuickEnter` 배선 회귀 테스트** (검수관 게이트 명세, 2026-08-08 · `ebf9efe`).
  '캐릭터 꾸미기' 버튼이 **폼을 펼치는 것과 편집기를 여는 것 둘 다** 하는지 지키는
  검사가 0건이다(`tests/` 에 `ui-hud.ts` 커버리지 없음). 한쪽만 참인 통과는 반려다 —
  `openChibiMaker()` 한 줄이 사라지면 감독 지시("바로 편집창으로")가 조용히 무효가 되고
  화면에는 예전처럼 폼만 펼쳐진다.
  처방: `ui-hud.ts` 를 실제 import 하고 `createChibiMaker`(three 의존)만 `open: vi.fn()`
  반환 팩토리로 스텁 교체(`tests/world2-sky-system.test.ts` 패턴). 단언 ⑴
  `formWrap.classList.contains('lu-collapsed') === false` ⑵ 스텁 `open` 호출 1회.
  **거짓 FAIL 위험**: jsdom 에는 opacity 트랜지션이 없으므로 판정을 클래스·호출로만
  잡는다(opacity 축은 브라우저 스모크 몫). 스텁을 안 걸면 100% FAIL 인데 그건 측정
  실패이지 회귀 검출이 아니다.
  검출력 확인: `openChibiMaker();` 줄을 지우는 뮤테이션에 깨져야 인정. G3 와 같은 패턴의
  사각이라 **함께 처리하는 편이 싸다**(둘 다 three 스텁 구동이 필요하다).

- **G-VL1 — `verify-live` 404 검출력 회귀 테스트** (검수관 명세, 2026-08-07 · `7a08293`).
  `tests/` 에 `verify-live` 커버리지가 **0건**이라 이 파일 전체가 무보호다. 검출력 확인은
  검수관이 손으로 돌린 1회성 실측이었지 게이트가 아니다. 명세 전문(단언 3종·거짓 FAIL
  위험·못 잡는 것)은 그 판정 기록에 있다 — **여기에 옮겨 적지 않는다.**
  요지: `checkPage` 를 export 하고 ⑴ 404 자산 ⑵ 정상 페이지 ⑶ `route.abort()` 한 자산
  세 픽스처로 단언한다. **실제 미디어로 abort 를 만들면 테스트가 flaky 해진다** —
  반드시 `route.abort()` 로 결정적으로.

- **G-VL3 — `webgl:true` 페이지의 자산 관측이 고정 타이머에 매달려 있다** (검수관 발견,
  팀장 상신 사안). 실측: 미술관에서 `networkidle` 은 **실제 자산을 하나도 안 보고
  654ms 에 끝나고**, 자산 실패 축의 실효 예산은 `WEBGL_WAIT_MS`(6000)+300ms 뿐이다.
  그 뒤 도착하는 404 는 전부 놓친다. **이번 ERR_ABORTED 변경 이전부터 있던 사각**이고
  독립이다. 처방(고정 타이머 → 씬 준비 신호 대기)은 설계 분기라 팀장 판정이 필요하다.

- **G3 — 카테고리 랜덤 배선 통합 테스트** (검수관 권고, 2026-08-07 · `f068d0a`).
  탭 재클릭 랜덤의 대상 목록(`randomTargets`)은 `renderPanel` 이 줄을 그리면서 채운다
  ("화면 = 랜덤 대상"). 그 배선에 **회귀 게이트가 0이다.** 검수관이 실측했다 —
  `renderPanel` 의 `randomTargets = []` 초기화를 지우면 **카테고리를 오갈 때 이전 탭의
  타깃이 누적**되어 엉뚱한 항목까지 굴러가는데, `tsc --noEmit` 0에러 · `vitest` 25/25
  **그대로 통과**한다(`ui-avatar-editor.ts` 를 import 하는 테스트가 저장소에 0건).
  지금 테스트로 고정된 것은 `random-pick.ts` 의 선택 규칙뿐이다.
  처방: `createChibiMaker` 를 three 스텁으로 실제 구동해 ⑴ 카테고리별 `randomTargets`
  길이가 그려진 줄 수와 일치하는지 ⑵ `randomizeActiveCategory` 후 값이 실제로 바뀌는지
  단언한다. **초기화 삭제·push 삭제 뮤테이션 중 최소 하나가 깨져야** 검출력 인정.
  이번 병합을 막지 않은 이유: 사용자 영향이 랜덤 품질 저하뿐이고(크래시·보안 없음)
  현재 코드 자체는 안전함이 코드 읽기로 확인됐다. 다만 **다음에 이 배선을 만지는
  사람에게는 아무 신호도 가지 않는다.**

- **G2 — 렌더 게이트 개폐 회귀 스모크** (검수관 조건부 승인 조건 C2, 2026-08-07).
  `render-gate.ts` 의 게이트를 **거는 쪽·푸는 쪽 배선 어느 것도 지금 검사가 없다.**
  뮤테이션으로 확인했다 — `ui-avatar-editor.ts` 의 `open()`/`close()` 에서
  `setSceneCover` 를 지워도 **단위테스트가 한 건도 안 깨진다**(M5·M6).
  · **close 쪽이 빠지면** 편집기를 닫아도 게이트가 남아 미술관이 멈춘 화면으로 보인다.
  · **open 쪽이 빠지면 더 나쁘다** — 아무 증상 없이 성능만 조용히 원래대로 돌아간다.
    감독 신고가 재발할 뿐 원인이 화면에 안 나타난다.
  처방(검수관 G2 명세): `smoke:vite` 에 1스텝 — 편집기를 **열고**(draw 가 줄어드는가)
  **닫고**(draw 가 다시 오르는가) `renderer.info.render.calls` 를 본다. 오버레이
  페이드아웃 0.3초 구간은 프레임이 튀므로 **500ms 뒤부터** 측정한다.
  이번 사이클에서 뺀 이유: `scripts/smoke/**` 는 배포 조립 레시피와 1:1 미러링이라
  같은 사이클에 섞으면 검수 범위가 커진다. 대신 배포 전 1회 실측으로 갈음했다
  (프레임당 draw 115 → 78 → 115, ×·ESC·✓ 세 경로) — **그건 게이트가 아니다.**
  우선순위 근거: 이 게이트의 소비자가 렌더 하나에서 **fps 자동조정까지 둘**로 늘었다
  (`main-perf.ts`). 배선이 끊기면 피해 범위도 함께 커진다.
