## 1. 폰트 정책 (2026-07-13 감독 결정)

| 구분 | 폰트 | weight | 라이선스 | 비고 |
|---|---|---|---|---|
| **한글** | **나눔고딕 NanumGothic** | 400 / 700 / 800 | SIL OFL 1.1 | `unicode-range`로 한글에만 적용 |
| **영문·숫자** | **Pretendard** | 200~700 | SIL OFL 1.1 | 로고·얇은 weight 완성도 |
| 폴백 | 시스템 스택 | — | — | `Helvetica Neue…Apple SD Gothic Neo…` |

- **단일 진실원본(SSOT)**: `@font-face`와 폰트 스택은 **`web/vendor/fonts/fonts.css` 한 곳에만** 정의한다(`:root { --app-font: … }`). 정책 변경은 이 파일만 고친다. 절대 다른 파일에 `@font-face`나 스택 문자열을 복붙하지 않는다.
  - **DOM**: 모든 화면(landing/guide/studio/index/design)과 생성기(team/valuation/devlog)는 fonts.css를 `<link rel="stylesheet">`로 참조하고 `font-family: var(--app-font)`만 쓴다. ui.js의 `--lu-font`도 `var(--app-font)`로 잇는다.
  - **캔버스/WebGL**(3D 씬 라벨 — 플라크·이름표·워터마크·의성어): `web/js/fonts.js`의 `getCanvasFont()`가 런타임에 `--app-font`(SSOT)를 읽어 쓴다(스택 재정의 없음). 캔버스는 그리는 시점에 폰트가 없으면 시스템 폰트로 폴백해 그대로 텍스처에 구워지므로(이후 교체 안 됨), 텍스처를 굽기 전 `ensureCanvasFonts()`(한글 프로브 `'가'`로 나눔 400/700/800 로드 보장)를 **await**한다 — `createArtworks()` 앞. **순서 주의**: fonts.css는 index.html `<head>`의 정적 `<link>`라 main.js 실행 전 이미 문서에 존재해야 한다(런타임 주입 시 `document.fonts.load`가 @font-face를 못 찾는 콜드 로드 레이스 발생 — 검수 반려 사례).
- **매칭**: 나눔고딕 `unicode-range: U+1100-11FF, U+3130-318F, U+A960-A97F, U+AC00-D7A3, U+D7B0-D7FF`(한글) → **한글은 나눔고딕**, 라틴은 범위 밖이라 **Pretendard**로 자동 폴백.
- **self-host**: `web/vendor/fonts/*.woff2`. 앱 CSP(`default-src 'self'`, `style-src 'self' 'unsafe-inline'`)와 정합(외부 CDN 미사용, 동일 출처 `<link>` 허용). `font-display: swap`. fonts.css의 `src: url()`은 그 파일 기준 상대경로라 페이지 위치와 무관하게 동일 해석 — `<link href>` 접두(루트=`./app/…`, 앱=`./…`, 생성기=`../app/…`)만 위치별로 다르다.
- **성능**: 상용(KS X 1001 2350자) 서브셋으로 용량 최소화.
- **한계(인지)**: 나눔고딕은 Regular/Bold/ExtraBold뿐이라 얇은~중간 한글 weight(200/300/500/600)는 400/700로 근사된다. 영문은 Pretendard라 전 weight 유지.

## 2. 디자인 콘셉트

### 목표 한 줄

> **게임처럼 쉽지만, 미술관처럼 조용하고, 럭셔리 플랫폼처럼 정제된 UI.**

### 인상 우선순위 (이 순서로 판단한다)

1. **차분** — 화면은 소란하지 않다. 정보는 필요한 순간에만 나타난다.
2. **예술성** — 작품이 주인공, UI는 액자·조명·안내원 역할에 머문다.
3. **고급스러움** — 절제된 색·넉넉한 여백·신중한 모션으로 값을 매긴다.
4. **친근함** — 진입장벽 없이 조작이 직관적이다(어렵지 않음 ≠ 유치함).
5. **지적** — 정보 위계가 명확하고, 근거(AI 감상·작가 설명 등)가 잘 정리돼 있다.
6. **작품 집중** — 위 5가지가 흔들릴 때 항상 이 기준으로 되돌아온다: *이 화면이 작품을 더 잘 보이게 하는가?*

새 화면·컴포넌트를 판단할 때 이 순서를 그대로 우선순위로 쓴다. 예: "차분함"과 "친근함"이 충돌하면 차분함이 이긴다(친근함은 조작 난이도로 확보하고, 시각적 소란으로 확보하지 않는다).

### Animal Crossing: New Horizons 참고 범위

AC:NH는 **철학만** 참고한다 — 부담 없는 학습 곡선, 여유로운 리듬, 사용자를 다그치지 않는 톤.
**색·그래픽·아이콘·형태를 그대로 가져오는 것은 금지.** OpenArtShow는 "어린이용 귀여움"이
아니라 **프리미엄 미술 플랫폼**이다. 아야모(마스코트)가 존재한다고 해서 UI 전반이 캐주얼
게임처럼 보여선 안 된다 — 마스코트 노출은 절제(§12 참고).

### 표면별 톤 — 두 갈래 (2026-07-14 감독 확정 B안)

이 문서의 "조용한 럭셔리" 기조는 **작품을 보는 화면**의 기준이다. 단 **아바타 크리에이터
(아야모 꾸미기 모달)는 의도된 따뜻한 예외**로 둔다.

| 표면 | 톤 | 근거 |
|---|---|---|
| **작품 감상 화면** (홈·전시선택·3D 관람·작품상세·AI 관객반응·작가·관리) | **조용한 럭셔리** — 중립·저채도·초약 그림자·절제. 작품이 주인공. | 컬렉터·갤러리 신뢰, 작품 비충돌, IP 안전(전체 조합이 AC를 연상시키지 않음) |
| **아바타 크리에이터** (아야모 꾸미기) | **따뜻·포근한 프리미엄**(라운딩·부드러운 질감·친근한 촉감 허용) | 작품이 아니라 "내 캐릭터를 꾸미는 놀이 공간" — 친근함이 어울리는 유일한 표면 |

- **경계**: 이 예외는 **꾸미기 모달 한 곳에 국한**한다. 따뜻한 톤이 관람·관리 화면으로
  번지지 않게 한다(예외가 규칙을 잠식하면 "전체 조합 AC 연상" IP 리스크·프리미엄 훼손).
- **IP 안전선 유지**: 예외라 해도 §2 AC 참고 범위·§6 법무 하드게이트(로고·전용서체·주민
  복제·"동물의 숲" 문구 0)는 동일 적용. "무드만, 식별요소 0."

### 안티패턴 (명시적 금지)

| 금지 | 이유 |
|---|---|
| 사이버펑크 톤(고채도 보라/시안 네온) | 청자 그린·크림 팔레트와 충돌, 작품보다 UI가 시선을 끔 |
| 네온 글로우·홀로그램 이펙트 | "조용한 미술관" 인상과 정반대 |
| 메타버스풍 UI(플로팅 3D 패널, 과한 글래스모피즘) | 럭셔리보다 게임/테크데모처럼 보임 |
| NFT 시각언어(그리드라인 배경, 크립토 뱃지, 무지개 그라데이션 테두리) | 미술 플랫폼 신뢰도를 해침 |
| 콤보/스코어 팝업류 게임 이펙트, 파티클, 컨페티 | §10 모션 규격에서 전면 금지 |

## 3. 색 — 청자 그린 시스템

### 3-1. 포인트 컬러 공식 지정

- **포인트 컬러 #1 (공식)**: `--green-500` **#5f9e7d** (청자 그린). 모든 CTA·포커스·선택
  상태·링크의 기본 액센트.
- **포인트 컬러 #2 (골드 계열 후보 — 🔶 감독 확정 필요)**: 소장/가격/한정 표시 등 "가치"를
  나타내는 보조 강조용 후보. §3-4 참고.
- **원칙**: 포인트는 1~2개만 쓴다. 대면적 배경 채움에 포인트 컬러를 쓰지 않는다(중립색이
  베이스, 포인트는 CTA·배지·포커스링·선택 표시 등 소면적 강조에만).

  위·프레임에는 절대 틴트/오버레이로 얹지 않는다.** 작품을 감싸는 프레임·배경은 항상
  무채색(화이트/웜그레이/샌드베이지)이어야 작품 고유색과 경쟁하지 않는다.

### 3-4. 포인트 컬러 #2 — 골드 (✅ 감독 확정 2026-07-14: 도입)

가치 신호(소장·가격·한정) 전용 보조 포인트. 명명 충돌을 피하려 **`--accent-gold-*`**로 명명한다.

| 토큰 | 값 | H/S/L | 대비(/paper) | 용도 |
|---|---|---|---|---|
| `--accent-gold-300` | #d9c193 | 39°/48%/71% | 1.69:1 | 워시/배경 소량 |
| `--accent-gold-500` | #b08a4e | 37°/39%/50% | 3.08:1 | 소장·가격 배지 액센트 |
| `--accent-gold-700` | #8a6a37 | 37°/43%/38% | 4.83:1 | 텍스트 사용 가능(AA) |

- **용도(확정)**: "소장 완료", "한정 판매", 가격 강조 등 **가치 신호**에 한해 극소량 사용.
  기본 CTA·내비게이션·포커스·선택은 계속 **청자 그린 단독**으로 간다(골드는 대면적·기본
  액션에 쓰지 않는다). 두 포인트가 한 화면에서 경쟁하지 않도록 골드는 "값을 매기는 자리"에만.
- **작품 비충돌 원칙 동일 적용**: 골드도 작품 이미지 위·프레임에 얹지 않는다.

**명명 충돌 해소 (✅ 확정)**: 기존 코드(`web/landing.html`, `web/design.html`)의
`--gold: #5f9e7d`는 실제로는 **그린값**이다(레거시). 신규 진짜 골드는 위처럼 **`--accent-gold-*`**로
따로 명명해 충돌을 원천 차단한다. 레거시 `--gold`(=그린)는 **`--green-500`의 별칭(deprecated)**으로
간주하며, 구현 시 호출부를 점진적으로 `--green-500`으로 이관한다(하위호환 위해 즉시 삭제하지
않음). 새 코드에서는 그린은 `--green-500`, 골드는 `--accent-gold-*`만 쓴다.

### 4-2. 작품명·전시명 전용 토큰 (신규)

작품명·전시명은 "크고 여유 있게" — 목록의 부속 정보(작가/연도/가격)보다 확실히 크고,

| 토큰 | 값 | weight | 용도 |
|---|---|---|---|
| `--fs-title-exhibition` | clamp(22px, 3vw, 32px) | 700 | 전시명(리스트/상세 헤더) |
| `--fs-title-artwork` | clamp(20px, 2.6vw, 26px) | 700 | 작품명(카드/상세 카드) |
| `--fs-meta` | 14px | 400 | 작가/연도/재료 등 부속 메타(작품명보다 최소 1단계 작음) |
| line-height | 1.3 (제목 전용, 본문의 1.7보다 타이트) | | 제목은 조밀하게, 본문은 넉넉하게 — 위계 분리 |

### 4-3. 세리프 — 에세이형 장문 전용 (✅ 감독 확정 2026-07-14: 도입, 조달·실사 후 적용)

- **적용 범위(한정)**: 큐레이터 평문·작가 노트·작품 설명 등 **에세이형 장문 텍스트에만**
  세리프(명조 계열)를 쓴다. 제목·라벨·배지·버튼·메타·UI 크롬은 계속 산세리프(§1) 유지.
  "지적·고급" 인상을 장문 읽기 경험에서만 확보하고, UI 일관성은 해치지 않는다.
- **폰트 조달·라이선스(선행 과제 — §6-2 법무)**: 한글 명조 오픈소스 후보를 실사한다.
  1순위 검토 = **본명조(Noto Serif KR / 본고딕과 짝인 Source Han Serif, SIL OFL 1.1)** —
  라이선스 명확·완성도 높음·self-host 가능. woff2 서브셋(KS X 1001 2350자)으로 용량 관리.
  라틴은 Pretendard 유지 또는 짝이 되는 라틴 세리프 1종 검토. **법무 OFL 조건·표시 확인
  후 도입.**
- **적용 방식**: `--font-serif` 토큰 신설(SSOT `fonts.css`에 `@font-face` 추가, §1 규약
  동일). 장문 컨테이너에만 `font-family: var(--font-serif)` 적용. `font-display: swap`,
  한글 `unicode-range`로 매칭. 로딩 부담을 줄이려 **관람 흐름에서 실제 장문이 나타나는
  화면에서만 지연 로드**하는 것도 검토.
- **적용 전까지**: 산세리프(나눔고딕 400 + `--lh-body-loose` 1.85)로 처리하고, 폰트
  조달·법무 실사 완료 후 장문 영역에 스왑한다(구현은 별도 태스크).

### 4-4. 한/영 균형

- 나눔고딕(한글)과 Pretendard(라틴)는 물리적 폰트가 달라 x-height·비주얼 사이즈가
  미세하게 다르다. 라틴이 상대적으로 커 보이는 경향 — 국영문 병기 라벨(예: 작가명 국문+영문)에서
  라틴 구간에 `font-size: 0.95em` 보정을 권장(하드 규칙 아님, 병기 라벨에 한정).
- 어절 보존(`word-break: keep-all`)은 모든 한글 텍스트에 기본 적용(문서 상단 원칙 재확인).

### 4-5. 과소 글씨 금지

- 실사용 텍스트(본문·라벨·배지·캡션 포함) 어디에서도 **12px(`--fs-caption`) 미만 금지**.
- 모바일 반응형이라도 `clamp()` 하한을 낮추지 않는다 — 화면이 좁다고 글자를 더 줄이지 않고
  레이아웃(줄바꿈·단계형 전환)으로 대응한다(§9).

## 5. 간격 · 라운드 · 그림자 규칙

### 5-1. 스페이싱 스케일

4px 그리드, "넓은 여백" 원칙에 맞춰 상위 단계는 넉넉하게 벌린다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--space-1` | 4px | 아이콘-텍스트 간격 등 최소 단위 |
| `--space-2` | 8px | 인라인 요소 간격 |
| `--space-3` | 12px | 칩/배지 내부 패딩 |
| `--space-4` | 16px | 카드 내부 기본 패딩 |
| `--space-5` | 24px | 카드 내부 넉넉한 패딩, 컴포넌트 간 간격 |
| `--space-6` | 32px | 카드 그리드 갭 |
| `--space-7` | 64px | 섹션 내부 블록 간 최소 간격 |
| `--space-8` | 96px | 섹션-섹션 간 간격(데스크톱) |

**넓은 여백 원칙**: 섹션 간 간격은 최소 `--space-7`(64px) 이상. 작품 이미지 주변은
카드 내부 패딩보다 한 단계 더 후하게(관람자 시선이 작품에서 바로 이탈하지 않도록 여백으로
"숨 쉴 자리"를 준다).

### 5-2. Radius — 역할 분리 체계

기존 `--r-card: 3px`(각짐 = 갤러리 플레이트 컨벤션)와 새 브리프의 "둥근 패널" 철학은
**역할로 분리**해 공존시킨다 — *작품/전시를 담는 프레임은 갤러리 컨벤션대로 각지게,
사용자가 손으로 조작하는 인터랙티브 요소는 둥글게.*

| 토큰 | 값 | 역할 | 각짐/둥긂 |
|---|---|---|---|
| `--r-plate` (구 `--r-card`, 값 동일·별칭) | 3px | 작품 카드·전시 카드·작가 카드 — 갤러리 플레이트 컨벤션 | 각짐 |
| `--r-control` | 10px | 버튼·인풋·칩·배지·아이콘 버튼 | 둥긂(약) |
| `--r-panel` | 12px | 모달·사이드 패널·AI 감상 카드 콘텐츠 영역 | 둥긂 |
| `--r-sheet` | 20px (상단 모서리만) | 하단 시트 | 둥긂(강, top only) |
| `--r-pill` | 999px | 완전 라운드가 필요한 태그/토글(예: 적용된 필터 칩) | 완전 둥긂 |

**원칙 요약**: "작품을 담는 것 = 각짐(존중·전시 컨벤션)", "사용자가 만지는 것 = 둥긂(손맛·친근함)".
`--r-card`는 하위 호환을 위해 `--r-plate`와 동일 값(3px)으로 유지한다.

### 5-3. 그림자 — 하향 조정

기존 `--shadow-card-hover`(0 16px 32px, 8% 투명도)는 "매우 약한 그림자" 기준에 비해
무겁다. 오프셋·블러·불투명도를 모두 낮춘 신규 값으로 하향한다(변수명은 유지 — 값만 교체하면
전역 반영).

| 토큰 | 기존 값 | 신규 값(하향) | 용도 |
|---|---|---|---|
| `--shadow-whisper` *(신규)* | — | `0 2px 6px rgba(20,38,29,.05)` | 기본 상태의 미세한 부상감(선택적) |
| `--shadow-card-hover` | `0 16px 32px rgba(20,38,29,.08)` | `0 6px 16px rgba(20,38,29,.06)` | 카드/버튼 hover 기본 |
| `--shadow-card-hover-deep` | `0 20px 40px rgba(63,122,92,.18)` | `0 10px 24px rgba(63,122,92,.12)` | featured 카드 hover |
| `--shadow-panel` *(신규)* | — | `0 8px 20px rgba(20,38,29,.10)` | 모달·시트·사이드 패널 부상감 |

원칙: 그림자는 "떠 있음"을 알려주는 최소 신호일 뿐, 무게감이나 극적 효과를 내는 용도가
아니다 — 값이 커질수록 럭셔리·차분함 인상과 멀어진다.

### 5-4. 구현 메모

색·타이포·스페이싱 토큰은 현재 §1 폰트처럼 SSOT 파일이 없고, `web/landing.html`,
`web/design.html`, `web/studio.html`, `web/guide.html` 각각의 `<style>:root{}`에
개별 정의돼 있다. 위 표의 신규/변경 토큰을 적용하려면 이 4개 파일의 `:root`를 모두
동기화해야 한다. 폰트처럼 공통 CSS 파일로 분리하는 것은 향후 개선 후보(이번 브리프
범위 밖, 별도 제안 필요).

## 6. 형태 · 인터랙션 원칙

- **radius/그림자**: §5 참조. 각진 플레이트=작품 프레임, 둥근 패널/컨트롤=인터랙티브 요소.
- **카드 hover**: 통일된 상승 `translateY(-4px)` + `--shadow-card-hover`(§5-3 하향값).
  featured는 `--shadow-card-hover-deep`로 더 깊게.
- **버튼**: hover `translateY(-2px)`+그림자, active `translateY(1px) scale(.98)`.
- **접근성**: `:focus-visible` 아웃라인(라이트 `--gold-text` / 다크 `--green-300`).
  `prefers-reduced-motion`에서 hover/active transform 무력화.

### UX 원칙 (모든 화면 설계에 적용)

1. **작품 우선** — 어떤 화면에서도 UI 크롬(버튼·라벨·배지)이 작품 이미지보다 시각적으로
   우세해선 안 된다. 크기·채도·대비 모두 작품에 양보한다.
2. **점진적 공개** — 정보는 기본정보 → 상세정보 단계로 연다(§8-4). 처음부터 다 보여주지 않는다.
3. **화면 중앙 보호** — 특히 3D 관람 화면에서 HUD·UI는 화면 중앙 시야를 가리지 않는다.
   요소는 가장자리·하단에 배치(§8-3, §9).
4. **쉬운 조작** — 터치 타겟 ≥44px, 되돌리기 항상 가능, 실수 방지(예: 파괴적 액션은
   2단계 확인). "쉬움"은 조작 난이도로 만들고 시각적 장식으로 만들지 않는다.

## 9. 반응형 기준

| 구간 | 폭 기준 | 레이아웃 원칙 |
|---|---|---|
| 모바일 | ~640px | **하단 시트 + 단계형 전환 우선.** 사이드 패널 금지(하단 시트로 대체). 탭은 필요시 하단 sticky. 터치 타겟 ≥44px |
| 태블릿 | 640~1024px | 하이브리드 — 사이드 패널·모달 병행 허용, 그리드 2~3열 |
| 데스크톱 | 1024~1440px | 사이드 패널·모달 기본, 그리드 3~4열 |
| 대형 TV/전시장 디스플레이(16:9) | ≥1440px, 4K 포함 | 콘텐츠 **최대폭 제한**(제안값 `--content-max-w: 1440px`, 확정 아님) — 화면이 넓다고 요소를 늘어뜨리지 않는다. 원거리 가독을 위해 텍스트 하한 상향, 인터랙션 요소 최소화(정적/자동 순환 중심) |
| 3D 오버레이 UI | 전 구간 공통 | 화면 중앙 40~50%는 항상 HUD 비배치 보호 영역(§6 UX 원칙 3). 안전영역(노치/베젤) 고려. HUD는 가장자리 고정 |

## 10. 화면 전환 · 마이크로 인터랙션 규격

| 대상 | 규격 |
|---|---|
| 카드 등장 | `translateY(12~16px) → 0` + `opacity 0 → 1`, 220~280ms, ease-out. 리스트는 40~60ms 스태거 |
| 버튼 hover 확대 | `scale(1.02~1.05)` 상한 — 이 이상 확대 금지 |
| 버튼 active | `translateY(1px) scale(.98)` |
| 팝업(모달/툴팁) 등장 | `scale(0.96~0.98) → 1` + fade, ease-out cubic. **오버슈트(바운스/스프링 이징) 금지** |
| 화면 전환 | 빠른 fade(150~200ms) 또는 방향성 있는 슬라이드(예: 상세→목록 뒤로가기)에 한정. 회전·큐브 전환 금지 |
| 선택 피드백 | 색보다 **형태(테두리/체크)·그림자·크기** 변화 우선 — 색만으로 상태 구분 금지(§7-0 공통 규칙과 동일 원칙) |

### 금지 목록

과한 바운스, 회전(rotate) 트랜지션, 파티클, 콤보/스코어 팝업류 게임 이펙트, 컨페티.
**모션은 시선 안내용으로만 쓴다** — "다음에 뭘 봐야 하는지" 알려주는 최소 신호. 장식용
모션은 지양하며, 항상 짧고 부드럽게 끝난다. `prefers-reduced-motion`에서는 §6 접근성
규칙대로 전 트랜지션 무력화.
