> 새 브리프가 우선**한다. 단 **§1 폰트 정책은 예외** — 이미 잘 정립된 결정이므로 변경 없이

## 1. 폰트 정책 (2026-07-13 감독 결정)

| 구분 | 폰트 | weight | 라이선스 | 비고 |
|---|---|---|---|---|
| **한글** | **나눔고딕 NanumGothic** | 400 / 700 / 800 | SIL OFL 1.1 | `unicode-range`로 한글에만 적용 |
| **영문·숫자** | **Pretendard** | 200~700 | SIL OFL 1.1 | 로고·얇은 weight 완성도 |
| 폴백 | 시스템 스택 | — | — | `Helvetica Neue…Apple SD Gothic Neo…` |

- **단일 진실원본(SSOT)**: `@font-face`와 폰트 스택은 **`web/vendor/fonts/fonts.css` 한 곳에만** 정의한다(`:root { --app-font: … }`). 정책 변경은 이 파일만 고친다. 절대 다른 파일에 `@font-face`나 스택 문자열을 복붙하지 않는다.
  - **DOM**: 모든 화면(landing/guide/studio/index/design)과 생성기(team/valuation/devlog)는 fonts.css를 `<link rel="stylesheet">`로 참조하고 `font-family: var(--app-font)`만 쓴다. ui.js의 `--lu-font`도 `var(--app-font)`로 잇는다.
  - **캔버스/WebGL**(3D 씬 라벨 — 플라크·이름표·워터마크·의성어): `web/js/fonts.js`의 `getCanvasFont()`가 런타임에 `--app-font`(SSOT)를 읽어 쓴다(스택 재정의 없음). 캔버스는 그리는 시점에 폰트가 없으면 시스템 폰트로 폴백해 그대로 텍스처에 구워지므로(이후 교체 안 됨), 텍스처를 굽기 전 `ensureCanvasFonts()`(한글 프로브 `'가'`로 나눔 400/700/800 로드 보장)를 **await**한다 — `createArtworks()` 앞. **순서 주의**: fonts.css는 index.html `<head>`의 정적 `<link>`라 main.js 실행 전 이미 문서에 존재해야 한다(런타임 주입 시 `document.fonts.load`가 @font-face를 못 찾는 콜드 로드 레이스 발생 — 검수 반려 사례).
- **매칭**: 나눔고딕 `unicode-range: U+1100-11FF, U+3130-318F, U+A960-A97F, U+AC00-D7A3, U+D7B0-D7FF`(한글) → **한글은 나눔고딕**, 라틴은 범위 밖이라 **Pretendard**로 자동 폴백.
- **self-host**: `web/vendor/fonts/*.woff2`. 앱 CSP(`default-src 'self'`, `style-src 'self' 'unsafe-inline'`)와 정합(외부 CDN 미사용, 동일 출처 `<link>` 허용). `font-display: swap`. fonts.css의 `src: url()`은 그 파일 기준 상대경로라 페이지 위치와 무관하게 동일 해석 — `<link href>` 접두(루트=`./app/…`, 앱=`./…`, 생성기=`../app/…`)만 위치별로 다르다.
- **성능**: 상용(KS X 1001 2350자) 서브셋으로 용량 최소화.
- **한계(인지)**: 나눔고딕은 Regular/Bold/ExtraBold뿐이라 얇은~중간 한글 weight(200/300/500/600)는 400/700로 근사된다. 영문은 Pretendard라 전 weight 유지.

## 2. 디자인 콘셉트

> **2026-07-14 감독 B안 갱신**: 아래 목표 한 줄·인상 우선순위·안티패턴은 §3 새 팔레트(바이올렛·
> 시안·코랄) 채택에 맞춰 재정렬됐다. "작품이 주인공" 원칙은 그대로 유지하되, "차분함이
> 최우선"이라는 낡은 프레이밍은 폐기한다 — 새 팔레트는 다크 몰입 표면(로비·3D 갤러리)에서
> 의도적으로 생동감을 낸다. 구 콘셉트("조용한 럭셔리" 전제)는 §13 부록에 보존.

### 목표 한 줄

> **활기찬 디지털 아트 플랫폼처럼 생동감 있게, 그러나 미술관처럼 신뢰할 수 있게 —
> 작품이 항상 주인공인 UI.** (활기차되 싸구려 아님)

### 인상 우선순위 (이 순서로 판단한다)

1. **예술성** — 작품이 주인공, UI는 액자·조명·안내원 역할에 머문다. 아래 순위가 흔들릴 때
   항상 여기로 되돌아온다.
2. **활기** — 다크 몰입(로비·3D 갤러리)과 라이트 에디토리얼(작품·카탈로그)이 생동감 있게
   대비를 이룬다. 저채도로 숨죽이지 않되, 액센트 규율(§3-6)로 과잉을 막는다.
3. **신뢰** — 절제된 액센트 비율(합 ≤18%, §3-6)·정확한 정보 위계·신중한 모션(§10)으로
   "싸구려 디지털 플랫폼"이 아니라 "믿을 수 있는 아트 플랫폼" 인상을 준다.
4. **친근함** — 진입장벽 없이 조작이 직관적이다(어렵지 않음 ≠ 유치함).
5. **지적** — 정보 위계가 명확하고, 근거(AI 감상·작가 설명 등)가 잘 정리돼 있다.
6. **작품 집중** — 위 5가지가 흔들릴 때 항상 이 기준으로 되돌아온다: *이 화면이 작품을 더 잘 보이게 하는가?*

새 화면·컴포넌트를 판단할 때 이 순서를 그대로 우선순위로 쓴다. 예: "활기"와 "신뢰"가 충돌하면
(예: 화면 하나에 액센트를 몰아 넣고 싶은 유혹) 신뢰가 이긴다 — 액센트 규율(§3-6)이 항상
상한선이다.

> **변경 근거**: 기존 "차분함 최우선" 기조는 채도를 낮춘 청자 그린·크림 팔레트를 전제로 했다.
> 새 팔레트는 다크 몰입 30%를 포함해 의도적으로 생동감을 낸다 — "차분함"을 UI의 절대선으로
> 두지 않고, 대신 "작품 우선(1순위)·액센트 규율(§3-6)"로 시각적 소란을 통제한다.

### Animal Crossing: New Horizons 참고 범위

AC:NH는 **철학만** 참고한다 — 부담 없는 학습 곡선, 여유로운 리듬, 사용자를 다그치지 않는 톤.
**색·그래픽·아이콘·형태를 그대로 가져오는 것은 금지.** OpenArtShow는 "어린이용 귀여움"이
아니라 **활기찬 프리미엄 미술 플랫폼**이다("활기차되 싸구려 아님" — 목표 한 줄 참고). 아야모
(마스코트)가 존재한다고 해서 UI 전반이 캐주얼 게임처럼 보여선 안 된다 — 마스코트 노출은
절제(§12 참고).

### 표면별 톤 — 두 축 (라이트/다크는 §3-1, 따뜻함 예외는 아래)

톤을 결정하는 축은 **두 개, 서로 직교**한다.

1. **표면 모드(라이트 에디토리얼 vs 다크 몰입)** — 어느 화면이 어느 배경을 쓰는지의 문제.
   정확한 매핑표는 **§3-1**(색 토큰과 직결되므로 그쪽이 단일 진실원본). 라이트 에디토리얼
   (작품상세·카탈로그·관리)은 여전히 절제된 "조용한" 톤을 유지하고, 다크 몰입(로비·3D
   갤러리)은 새로 "생동감 있는" 톤을 취한다 — 위 인상 우선순위 개정과 정합.
2. **따뜻함 예외(아바타 크리에이터)** — 아래 표. 이 축은 라이트/다크와 무관하게 **꾸미기
   모달 한 곳에만** 적용되는 별도 예외다(기존 결정, 유지).

| 표면 | 톤 | 근거 |
|---|---|---|
| **아바타 크리에이터** (아야모 꾸미기) | **따뜻·포근한 프리미엄**(라운딩·부드러운 질감·친근한 촉감 허용) | 작품이 아니라 "내 캐릭터를 꾸미는 놀이 공간" — 친근함이 어울리는 유일한 표면 |
| **그 외 전 표면** | §3-1의 라이트/다크 모드 규칙을 그대로 따름 | 예외를 한 곳에 가둬 규칙 잠식을 막음 |

- **경계**: 이 예외는 **꾸미기 모달 한 곳에 국한**한다. 따뜻한 톤이 관람·관리 화면으로
  번지지 않게 한다(예외가 규칙을 잠식하면 "전체 조합 AC 연상" IP 리스크·프리미엄 훼손).
- **IP 안전선 유지**: 예외라 해도 §2 AC 참고 범위·§6 법무 하드게이트(로고·전용서체·주민
  복제·"동물의 숲" 문구 0)는 동일 적용. "무드만, 식별요소 0."

### 안티패턴 — 품질 가드레일 (2026-07-14 감독 B안 재작성)

> 생동감 있는 액센트(바이올렛/시안/코랄)를 공식 채택했으므로 "고채도=금지"라는 낡은 전제가
> 더 이상 성립하지 않는다. 대신 **품질 가드레일**로 대체한다 — 생동감과 저가형 크립토/게임
> 룩을 가르는 구체적 선.

| 금지 | 이유 |
|---|---|
| **글로우 남용** — 과도한 발광 box-shadow·blur, 네온 사인 느낌 | 다크 몰입 표면에서도 "밝기 절제"가 원칙. 과한 글로우는 작품보다 UI 자체를 밝힌다 |
| **풀채도 네온 대비** — 고채도 배경 위에 또 다른 고채도 원색을 정면충돌시키는 배치 | 액센트는 소면적 강조용(§3-6) — 대면적을 원색으로 채우거나 원색끼리 맞세우지 않는다 |
| **움직이는(애니메이션) 그라디언트 배경** | §10 모션 절제 원칙과 충돌, 시선을 작품에서 뺏는 대표 패턴 |
| **바이올렛→시안 그라디언트** | 팔레트 중 **가장 강한 NFT/크립토 시각 시그널**. 두 색은 **항상 분리해서 사용**한다(같은 요소 안에서 섞지 않음) — §3-2 |
| **크립토/도박/무료게임 사이트 룩** — 뱃지 남발, 카운트다운 타이머, 팝업형 CTA, 반짝이는 보상연출 | 미술 플랫폼 신뢰도를 해침, 인상 우선순위 3(신뢰)와 정면 위반 |

## 3. 색 — 팔레트 B안 (2026-07-14 감독 확정)

> 아트바젤·프리즈·AAF(Art Auction Fair) 등 실물 아트페어의 "화이트큐브 + 몰입 라운지"
> 이원 구성을 참조해, 감독이 새 팔레트를 확정했다. 구 "청자 그린 시스템"은 폐기가 아니라
> **§13 부록 '구 팔레트(보존)'로 이관**해 복원 경로를 유지한다. 이 절(§3)이 바뀌어도
> §4~§12(타이포·스페이싱·radius·컴포넌트 뼈대·와이어프레임·반응형·모션)는 색과 직교하므로
> 그대로 보존되며, 각 절에서 색 토큰을 직접 참조하던 곳만 새 토큰명으로 갱신 표기했다.

### 3-1. 이원 표면 구조 — 라이트 에디토리얼 / 다크 몰입

**모든 화면은 둘 중 하나의 표면 모드에 속한다.** 배경·본문 텍스트 앵커 토큰은 표면 모드가
결정한다 — 개별 컴포넌트가 임의로 반대 모드의 배경색을 쓰지 않는다.

| 표면 | 모드 | 배경 토큰 | 본문 텍스트 토큰 | 근거 |
|---|---|---|---|---|
| 로비 / 홈(3D 진입 전) | **다크 몰입** | `--bg-dark` #14151A | `--text-light` #F5F5F2 | 첫인상 — 몰입감·생동감 우선 |
| 3D 갤러리 관람 | **다크 몰입** | `--bg-dark` | `--text-light` | HUD 대비 설계는 §8-3 스켈레톤 그대로, 배경만 다크 앵커로 정박 |
| 작품 상세 페이지 | **라이트 에디토리얼** | `--bg-light` #F3F0E9 | `--text-dark` #202124 | 작품 색과 경쟁 없는 중립 배경 — §3-6 작품 비충돌 원칙 |
| 전시 카탈로그 · 리스트 | **라이트 에디토리얼** | `--bg-light` | `--text-dark` | |
| 작가 프로필 | **라이트 에디토리얼** | `--bg-light` | `--text-dark` | |
| 관리(작가·갤러리 어드민) | **라이트 에디토리얼** | `--bg-light` | `--text-dark` | §8-7 스켈레톤(카드형 대시보드) 그대로, 색만 갱신 |
| AI 관객 반응 | **라이트 에디토리얼** | `--bg-light` | `--text-dark` | 작품 상세에 종속된 서브 화면 |
| 아바타 크리에이터(아야모 꾸미기) | **라이트 계열 + 따뜻 예외**(§2) | `--bg-light` 기반, 웜톤 보정 | `--text-dark` | 톤의 예외축(§2)과 표면축(본 표)은 직교 — 배경 계열은 라이트 |

- **원칙**: 다크 몰입은 순수 검정(`#000`)을 쓰지 않는다 — **`#14151A`가 항상 다크 앵커**다
  (§3-6 액센트 규율과 동일 원칙). 라이트 에디토리얼의 배경은 `#F3F0E9`로, 구 `--paper`
  (#fdfbf5, 크림)보다 살짝 차분하고 채도 낮은 웜그레이-베이지다.
- **레거시 정리**: `--paper`/`--paper-deep`(크림톤)는 페이지 레벨 배경 앵커 역할을
  `--bg-light`에 넘기고 §13 부록으로 이관한다(즉시 삭제 아님 — 하위호환 별칭으로 유지 가능).
  카드 내부의 중립 회색조 스케일(`--neutral-white`/`--neutral-sand-*`/`--neutral-warm-gray-*`/
  `--ink`·`--ink-body`·`--ink-dim`)은 `--bg-light`(H42° S29% L93%)와 색상 계열이
  근접해 **그대로 유지**한다(구 스케일 원본은 §13-2 — 색과 직교하는 뼈대로 취급).

### 3-2. 액센트 3색 — 의미 역할 매핑 (감독 확정)

| 토큰 | 값 | 역할 | 사용 표면 |
|---|---|---|---|

- **바이올렛→시안 그라디언트 금지**(§2 안티패턴): 두 색은 팔레트 내 가장 강한 NFT 시그널
  조합이므로 같은 요소·같은 방향성 그라데이션에 **함께 쓰지 않는다.** 한 화면에 공존은
  가능하되(예: 3D 관람 HUD의 선택 표시=바이올렛, 실시간 관람객 배지=시안) 서로 다른 요소에
  분리 배치한다.
- **코랄 = CTA/입장/티켓 전용**: 장식용(로고 방점, 배경 워시 등)으로 쓰지 않는다. 코랄이
  보이면 사용자가 "누르면 무언가 진행된다"고 신뢰할 수 있어야 한다.

### 3-3. 접근성 실측 — 원색 대비 (WCAG)

세 원색은 **다크 배경(#14151A) 전용**이다. 라이트 배경(#F3F0E9) 위 텍스트로는 AA(4.5:1)는
물론 3:1(대형 텍스트/UI 컴포넌트 경계) 다수 기준도 통과하지 못한다 — 아래 실측치.

| 색 | H/S/L | 대비(`/#14151A` 다크 BG) | 대비(`/#F3F0E9` 라이트 BG) | 라이트 배경 텍스트 |
|---|---|---|---|---|
| `--violet-500` #8B72FF | 250.6°/100%/72.4% | **5.16:1** — 본문 AA 통과 | 3.10:1 | **불가**(본문 AA 미달, 대형 텍스트 3:1은 통과) |
| `--cyan-500` #72E6E1 | 177.4°/69.9%/67.5% | **12.26:1** — 여유 통과 | 1.31:1 | **완전 불가**(대형 텍스트 기준조차 미달) |
| `--coral-500` #FF705E | 6.7°/100%/68.4% | **6.71:1** — 본문 AA 통과 | 2.39:1 | **불가**(대형 텍스트 3:1도 미달) |
| 참고 `--text-dark` #202124 | 225°/5.9%/13.3% | — | **14.15:1** | 가능(라이트 표면 기본 본문) |
| 참고 `--text-light` #F5F5F2 | 60°/13%/95.5% | **16.69:1** | — | 가능(다크 표면 기본 본문) |

**결론(규정)**: Violet/Cyan/Coral 원색은 **다크 배경 전용 텍스트·아이콘·채움**으로만 쓴다.
라이트 에디토리얼 표면에서 이 셋을 텍스트·아이콘·채움(배경 fill) 색으로 직접 쓰는 것을
금지한다 — 대신 아래 §3-4의 라이트 표면용 다크 변형(`-ink`) 토큰을 쓴다.

### 3-4. 라이트 표면용 다크 변형 — `-ink` 토큰 (신규, 접근성 필수)

**채도(S)는 그대로 두고 명도(L)만 낮춰** 라이트 배경(#F3F0E9) 위에서 본문 AA(4.5:1)를
통과시킨 변형이다(채도 상향 금지 — §3-5 스케일과 동일 원칙). 각 색의 100~900 스케일에서
AA를 통과하는 단계를 그대로 `-ink` 별칭으로 지정했다(§3-5의 700/800단과 동일 값).

| 토큰 | 값 | H/S/L | 대비(`/#F3F0E9`) | 대비(`/#14151A`) | 판정 |
|---|---|---|---|---|---|
| `--violet-ink` (=`--violet-700`) | #5733FF | 250.6°/100%/60% | **5.55:1** | 2.88:1 | AA 본문 통과(라이트 전용), 다크 배경에선 사용 안 함 |
| `--cyan-ink` (=`--cyan-800`) | #136C68 | 177.4°/69.9%/25% | **5.47:1** | 2.93:1 | AA 본문 통과(라이트 전용) |
| `--coral-ink` (=`--coral-800`) | #CC1700 | 6.7°/100%/40% | **5.00:1** | 3.20:1 | AA 본문 통과(라이트 전용) |

- 세 토큰 모두 4.5:1 문턱에 여유 마진(+0.5~1.0)을 두고 골랐다 — hex 반올림에 따른 미세
  오차를 흡수하기 위함. 대형 텍스트(3:1)·비텍스트 UI 컴포넌트 경계(3:1)는 당연히 통과.
- **채워진(filled) UI에서 라벨 색 규칙** — 배경 fill이 accent 색일 때 그 위에 얹는 텍스트/
  아이콘 라벨 색은 fill의 종류에 따라 갈린다(실측):

| 라벨 텍스트 | 원색 fill(다크 표면용) 위 대비 | ink 변형 fill(라이트 표면용) 위 대비 |
|---|---|---|
| `--text-dark` #202124 | violet 4.56:1 · cyan 10.83:1 · coral 5.93:1 (**전부 AA 통과 — 원색 fill엔 text-dark**) | violet-ink 2.55:1 · cyan-ink 2.59:1 · coral-ink 2.83:1 (미달) |
| `--text-light` #F5F5F2 | violet 3.23:1 · cyan 1.36:1 · coral 2.49:1 (미달 — 원색 fill엔 text-light 쓰지 않음) | violet-ink 5.79:1 · cyan-ink 5.70:1 · coral-ink 5.21:1 (**전부 AA 통과 — ink fill엔 text-light**) |

  → **규칙**: 다크 표면의 원색 채움 위엔 `--text-dark` 라벨, 라이트 표면의 `-ink` 채움
  위엔 `--text-light` 라벨. (반대로 조합하면 대비 미달.)

### 3-8. 작품 비충돌 원칙(재확인)

액센트는 UI 크롬(버튼·배지·링크·포커스·HUD)에만 사용하고, **작품 이미지 위·프레임에는
절대 틴트/오버레이로 얹지 않는다**(§3-6과 동일 규율, 구 그린 시스템의 원칙을 그대로 승계).
작품을 감싸는 프레임·배경은 항상 중립(라이트: 화이트/웜그레이/샌드베이지, 다크: `--bg-dark`
계열 무채색)이어야 작품 고유색과 경쟁하지 않는다.

### 3-9. 구 팔레트(그린·골드) 처리

구 "청자 그린 시스템"(`--green-100~900`, `--gold-text`)과 포인트 컬러 #2 골드
(`--accent-gold-*`)는 **삭제하지 않고 §13 부록 '구 팔레트(보존)'로 이관**한다. 신규
팔레트에는 "가치 신호(소장·가격·한정)" 역할에 대응하는 색이 아직 없다 — 골드가 담당하던
역할의 신규 배정 여부는 **감독 확정 필요 항목**으로 남긴다(§3-2는 선택/온라인/CTA 3역할만
정의).

| `--fs-meta` | 14px | 400 | 작가/연도/재료 등 부속 메타(작품명보다 최소 1단계 작음) |
| line-height | 1.3 (제목 전용, 본문의 1.7보다 타이트) | | 제목은 조밀하게, 본문은 넉넉하게 — 위계 분리 |

### 4-3. 세리프 — 에세이형 장문 전용 (✅ 감독 확정 2026-07-14: 도입, 조달·실사 후 적용)

- **적용 범위(한정)**: 큐레이터 평문·작가 노트·작품 설명 등 **에세이형 장문 텍스트에만**
  세리프(명조 계열)를 쓴다. 제목·라벨·배지·버튼·메타·UI 크롬은 계속 산세리프(§1) 유지.
  "지적·고급" 인상을 장문 읽기 경험에서만 확보하고, UI 일관성은 해치지 않는다.
- **폰트 조달·라이선스(선행 과제 — §6-2 법무)**: 한글 명조 오픈소스 후보를 실사한다.
  1순위 검토 = **본명조(Noto Serif KR / 본고딕과 짝인 Source Han Serif, SIL OFL 1.1)** —
  라이선스 명확·완성도 높음·self-host 가능. woff2 서브셋(KS X 1001 2350자)으로 용량 관리.
  라틴은 Pretendard 유지 또는 짝이 되는 라틴 세리프 1종 검토. **법무 OFL 조건·표시 확인
  후 도입.**
- **조달 완료(2026-07-14)**: Noto Serif KR을 조달·서브셋(한글 KS X 1001 2350자 311KB
  + 라틴 19KB) 후 `web/vendor/fonts/`에 self-host, `fonts.css`에 `@font-face`(family
  `NotoSerifKR`, weight 400, `unicode-range` 매칭) + **`--font-serif` 토큰** 추가 완료.
  라이선스: SIL OFL 1.1, THIRD-PARTY-NOTICES §7 + `NotoSerifKR-OFL.txt` 동봉.
- **적용 방식**: 에세이 장문 컨테이너에만 `font-family: var(--font-serif)`. `font-display:
  swap` + `unicode-range`라 **실제 장문(세리프)이 렌더되는 화면에서만 지연 다운로드**된다
  (현재 UI엔 미적용이라 사용자 다운로드 0). 제목·라벨·UI 전역은 계속 `--app-font`(나눔+
  Pretendard) 유지.

### 4-4. 한/영 균형

- 나눔고딕(한글)과 Pretendard(라틴)는 물리적 폰트가 달라 x-height·비주얼 사이즈가
  미세하게 다르다. 라틴이 상대적으로 커 보이는 경향 — 국영문 병기 라벨(예: 작가명 국문+영문)에서
  라틴 구간에 `font-size: 0.95em` 보정을 권장(하드 규칙 아님, 병기 라벨에 한정).
- 어절 보존(`word-break: keep-all`)은 모든 한글 텍스트에 기본 적용(문서 상단 원칙 재확인).

### 4-5. 과소 글씨 금지

- 실사용 텍스트(본문·라벨·배지·캡션 포함) 어디에서도 **12px(`--fs-caption`) 미만 금지**.
- 모바일 반응형이라도 `clamp()` 하한을 낮추지 않는다 — 화면이 좁다고 글자를 더 줄이지 않고
  레이아웃(줄바꿈·단계형 전환)으로 대응한다(§9).

## 5. 간격 · 라운드 · 그림자 규칙

### 5-1. 스페이싱 스케일

4px 그리드, "넓은 여백" 원칙에 맞춰 상위 단계는 넉넉하게 벌린다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--space-1` | 4px | 아이콘-텍스트 간격 등 최소 단위 |
| `--space-2` | 8px | 인라인 요소 간격 |
| `--space-3` | 12px | 칩/배지 내부 패딩 |
| `--space-4` | 16px | 카드 내부 기본 패딩 |
| `--space-5` | 24px | 카드 내부 넉넉한 패딩, 컴포넌트 간 간격 |
| `--space-6` | 32px | 카드 그리드 갭 |
| `--space-7` | 64px | 섹션 내부 블록 간 최소 간격 |
| `--space-8` | 96px | 섹션-섹션 간 간격(데스크톱) |

**넓은 여백 원칙**: 섹션 간 간격은 최소 `--space-7`(64px) 이상. 작품 이미지 주변은
카드 내부 패딩보다 한 단계 더 후하게(관람자 시선이 작품에서 바로 이탈하지 않도록 여백으로
"숨 쉴 자리"를 준다).

### 5-2. Radius — 역할 분리 체계

기존 `--r-card: 3px`(각짐 = 갤러리 플레이트 컨벤션)와 새 브리프의 "둥근 패널" 철학은
**역할로 분리**해 공존시킨다 — *작품/전시를 담는 프레임은 갤러리 컨벤션대로 각지게,
사용자가 손으로 조작하는 인터랙티브 요소는 둥글게.*

| 토큰 | 값 | 역할 | 각짐/둥긂 |
|---|---|---|---|
| `--r-plate` (구 `--r-card`, 값 동일·별칭) | 3px | 작품 카드·전시 카드·작가 카드 — 갤러리 플레이트 컨벤션 | 각짐 |
| `--r-control` | 10px | 버튼·인풋·칩·배지·아이콘 버튼 | 둥긂(약) |
| `--r-panel` | 12px | 모달·사이드 패널·AI 감상 카드 콘텐츠 영역 | 둥긂 |
| `--r-sheet` | 20px (상단 모서리만) | 하단 시트 | 둥긂(강, top only) |
| `--r-pill` | 999px | 완전 라운드가 필요한 태그/토글(예: 적용된 필터 칩) | 완전 둥긂 |

**원칙 요약**: "작품을 담는 것 = 각짐(존중·전시 컨벤션)", "사용자가 만지는 것 = 둥긂(손맛·친근함)".
`--r-card`는 하위 호환을 위해 `--r-plate`와 동일 값(3px)으로 유지한다.

### 5-3. 그림자 — 하향 조정

기존 `--shadow-card-hover`(0 16px 32px, 8% 투명도)는 "매우 약한 그림자" 기준에 비해
무겁다. 오프셋·블러·불투명도를 모두 낮춘 신규 값으로 하향한다(변수명은 유지 — 값만 교체하면
전역 반영).

| 토큰 | 기존 값 | 신규 값(하향) | 용도 |
|---|---|---|---|
| `--shadow-whisper` *(신규)* | — | `0 2px 6px rgba(20,21,26,.05)` | 기본 상태의 미세한 부상감(선택적) |
| `--shadow-card-hover` | `0 16px 32px rgba(20,38,29,.08)` | `0 6px 16px rgba(20,21,26,.06)` | 카드/버튼 hover 기본 |
| `--shadow-card-hover-deep` | `0 20px 40px rgba(63,122,92,.18)` | `0 10px 24px rgba(139,114,255,.16)` | featured 카드 hover(강조색: `--violet-500` 틴트) |
| `--shadow-panel` *(신규)* | — | `0 8px 20px rgba(20,21,26,.10)` | 모달·시트·사이드 패널 부상감 |

> **2026-07-14 팔레트 B안 갱신**: 그림자 틴트는 값(오프셋·블러·불투명도)은 그대로 두고 색만
> 갱신했다. 구 rgba(20,38,29)/(63,122,92)는 청자 그린 900/700의 rgb값이었다 — 신규는
> `--bg-dark`(20,21,26)를 기본 틴트로, featured 강조만 `--violet-500`(139,114,255)로 바꿨다.

원칙: 그림자는 "떠 있음"을 알려주는 최소 신호일 뿐, 무게감이나 극적 효과를 내는 용도가
아니다 — 값이 커질수록 럭셔리·차분함 인상과 멀어진다.

### 5-4. 구현 메모

색·타이포·스페이싱 토큰은 현재 §1 폰트처럼 SSOT 파일이 없고, `web/landing.html`,
`web/design.html`, `web/studio.html`, `web/guide.html` 각각의 `<style>:root{}`에
개별 정의돼 있다. 위 표의 신규/변경 토큰을 적용하려면 이 4개 파일의 `:root`를 모두
동기화해야 한다. 폰트처럼 공통 CSS 파일로 분리하는 것은 향후 개선 후보(이번 브리프
범위 밖, 별도 제안 필요).

## 6. 형태 · 인터랙션 원칙

- **radius/그림자**: §5 참조. 각진 플레이트=작품 프레임, 둥근 패널/컨트롤=인터랙티브 요소.
- **카드 hover**: 통일된 상승 `translateY(-4px)` + `--shadow-card-hover`(§5-3 하향값).
  featured는 `--shadow-card-hover-deep`로 더 깊게.
- **버튼**: hover `translateY(-2px)`+그림자, active `translateY(1px) scale(.98)`.
- **접근성**: `:focus-visible` 아웃라인(라이트 `--violet-ink` / 다크 `--violet-500` — 2026-07-14
  팔레트 B안 갱신, 포커스=선택/정체성 역할이라 §3-2 매핑에 따라 바이올렛 계열로 통일. 구
  `--gold-text`/`--green-300`은 §13 부록).
  `prefers-reduced-motion`에서 hover/active transform 무력화.

### UX 원칙 (모든 화면 설계에 적용)

1. **작품 우선** — 어떤 화면에서도 UI 크롬(버튼·라벨·배지)이 작품 이미지보다 시각적으로
   우세해선 안 된다. 크기·채도·대비 모두 작품에 양보한다.
2. **점진적 공개** — 정보는 기본정보 → 상세정보 단계로 연다(§8-4). 처음부터 다 보여주지 않는다.
3. **화면 중앙 보호** — 특히 3D 관람 화면에서 HUD·UI는 화면 중앙 시야를 가리지 않는다.
   요소는 가장자리·하단에 배치(§8-3, §9).
4. **쉬운 조작** — 터치 타겟 ≥44px, 되돌리기 항상 가능, 실수 방지(예: 파괴적 액션은
   2단계 확인). "쉬움"은 조작 난이도로 만들고 시각적 장식으로 만들지 않는다.

### 7-4. 작품 카드

> **2026-07-14 팔레트 B안 — 규칙 변경(단순 토큰 치환 아님)**: §3-6 액센트 규율
> "작품 이미지·프레임·캡션엔 액센트 절대 금지"가 신설되면서, 구 스펙의 hover/selected
> 테두리 액센트 색(`--green-500`/`--green-700`)은 그대로 이관할 수 없다. **프레임 자체는
> 중립으로 유지**하고, 액센트가 필요한 선택 신호는 프레임과 분리된 **배지**(UI 크롬이라
> 액센트 허용)로만 표현한다.

## 10. 화면 전환 · 마이크로 인터랙션 규격

| 대상 | 규격 |
|---|---|
| 카드 등장 | `translateY(12~16px) → 0` + `opacity 0 → 1`, 220~280ms, ease-out. 리스트는 40~60ms 스태거 |
| 버튼 hover 확대 | `scale(1.02~1.05)` 상한 — 이 이상 확대 금지 |
| 버튼 active | `translateY(1px) scale(.98)` |
| 팝업(모달/툴팁) 등장 | `scale(0.96~0.98) → 1` + fade, ease-out cubic. **오버슈트(바운스/스프링 이징) 금지** |
| 화면 전환 | 빠른 fade(150~200ms) 또는 방향성 있는 슬라이드(예: 상세→목록 뒤로가기)에 한정. 회전·큐브 전환 금지 |
| 선택 피드백 | 색보다 **형태(테두리/체크)·그림자·크기** 변화 우선 — 색만으로 상태 구분 금지(§7-0 공통 규칙과 동일 원칙) |

### 금지 목록

과한 바운스, 회전(rotate) 트랜지션, 파티클, 콤보/스코어 팝업류 게임 이펙트, 컨페티.
**모션은 시선 안내용으로만 쓴다** — "다음에 뭘 봐야 하는지" 알려주는 최소 신호. 장식용
모션은 지양하며, 항상 짧고 부드럽게 끝난다. `prefers-reduced-motion`에서는 §6 접근성
규칙대로 전 트랜지션 무력화.
