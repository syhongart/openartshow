# 뉴욕 갤러리 거리 — 합격 조건 (acceptance)

지시서 `docs/NYC-GALLERY-WALK.md` §7(예산)·§11(합격 조건)을 이 저장소의 실측 조건으로 옮긴 것이다. **여기 수치는 Baseline 에서 한 번 조정한 뒤 고정한다** — 바꿀 때는 이유와 이전/새 수치를 이 파일에 남긴다(§7).

## 0. 기준 장치·측정 조건 (Baseline 2026-09-06)

| 축 | 확보 상태 | 비고 |
|---|---|---|
| 헤드리스 Chromium(swiftshader, WebGL) 900×560·DPR 1 | **있음** | 삼각형·draw·개수·전송량·화면 구도만. **프레임 시간은 근거가 아니다**(CPU 래스터). 블룸 안 켜짐 |
| 감독 실기기(WebGPU, 모바일) | 링크 확인만 | 프레임 체감·룩 판정의 유일한 축. 수치는 못 받는다 |
| iPhone Safari / Android Chrome 계측 | **없음** | 미검증으로 남긴다 |
| 데스크톱 GPU 브라우저 계측 | **없음** | 미검증 |

## 2. 시각·기능 합격 (지시서 §11 그대로, 판정 수단 추가)

| 영역 | 통과 조건 | 판정 수단 |
|---|---|---|
| 첫인상 | 시작 화면에서 갤러리 거리라는 목적과 첫 입장 위치가 읽힌다. 문·창·층·보도 관계가 보인다 | 시점 1 캡처 → 디자이너 육안 + 감독 카드 |
| 일관성 | 6 시점 모두 같은 팔레트·명암 언어. 과한 암부·안개·블룸 없이 깊이 유지 | 6 시점 캡처(같은 카메라·FOV·시간대·seed) → 디자이너 |
| 이동 | 거리↔실내 왕복에 막힘·벽 통과 없음. 깜빡임·관통·팝인 없음 | 30초 고정 경로 프레임 시퀀스 → QA(executor) |
| 전시 | 종횡비 다른 작품 설치·교체 → 저장·새로고침 복원. 건물 에셋 재생성 없음 | 실행 테스트(vitest 통합 + 헤드리스 새로고침) |
| 작품 품질 | 잘림·늘어남 없음. 확대 감상에서 노을·블룸이 색·대비를 크게 바꾸지 않음 | 시점 5 캡처(day vs sunset) 픽셀 대조 |
| 성능 | §1 예산 통과, 재입장 후 리소스 증가 없음 | 스크립트 + `[7]` |
| 기존 동작 | 관람·계정(mock)·저장·시간대·조작 흐름이 지정 경로에서 동작 | 기존 테스트 + smoke:vite |
| 보고 | 코드·명령·전후 화면·동작·성능 표·제한이 서로 일치 | 검수관 |

## 3. 6 고정 시점 (지시서 §9)

거리 시작 · 대표 외관 근접 · 입구에서 실내 보기 · 실내 전체 · 작품 근접 · 실내에서 거리 보기. 카메라 좌표·yaw·FOV 는 `docs/nyc/art-direction.md` 의 값을 쓰고, 캡처 진입 수단은 팀장 판정(state.md) 에 따른다. seed 고정, 바람·구름 정지, 시간대 고정(늦은 오후 = `sunset` 인지 `day` 인지는 아트 기준이 정한다).

## 4. 반복 종료 규칙 (지시서 §10-7)

같은 문제가 3회 연속 개선되지 않으면 마지막 통과 상태를 보존하고 팀장이 범위 축소/설계 변경을 결정한다. «95점까지» 같은 근거 없는 종료 조건을 쓰지 않는다.
