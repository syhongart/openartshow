## 이 캡처가 **못 보는 것** (정직하게)

- **z-fighting 판정은 화면이 아니라 검사다.** 셀 경계 겹침 0 은 `tests/nyc-grid.test.ts`
  「셀 모드에도 동일 평면·같은 방향 겹침이 0 이다」가 잰다(정지 화면으로는 «이동하면
  우글거리는» 형태를 못 가른다 — 2026-09-06 회차에 실측된 한계다).
- **로딩이 안 걷힌 캡처를 하네스가 스스로 못 걸러낸다**(백로그 `G-CAP1`). 두 장 다 45~55초
  대기 뒤이고 화면에 세계가 서 있는 것을 눈으로 확인했다.
- 수치 표(초기 전송·draw·tri·개수 불변식)는 **캡처와 별개 실행**에서 `window.__glbWorld.stats()`
  로 읽었다 — 이 PNG 두 장에는 그 수치가 안 들어 있다.

## 2026-09-11 추가 — 밴드 SSOT 회차 (팀장 판정 B1)

`band05-V1.fogbug.png` ↔ `band05-V1.png` 비교는 **안개 축을 판정하지 못한다.** 정직하게 적는다:

- **V1 시점의 최원경이 게이트(≈59m)** 라 새 안개 밴드(시작 51.2m · 완전 76.8m)에서도 진행률이
  **30%** 에 그친다. 세계의 끝(76.8m)은 게이트와 양옆 건물에 가려 이 시점에서 **안 보인다.**
- 두 장의 **해상도가 다르다**(1280×720 ↔ 900×560 — 옛 것이 이 README 의 900×560 규약을
  벗어나 찍혔다). 픽셀 통계 비교가 그만큼 오염된다.
- 실측(픽셀 직접 계산): 게이트 개구부 L 147.5→150.4 · **sd 31.6→27.0**(원경 대비 14% 감소),
  근경 입면 sd 26.9→29.8. **방향은 안개가 낀 쪽이지만 크기가 작고 해상도 차이와 섞인다.**

그러므로 **「안개가 밴드를 따라온다」의 근거는 이 PNG 가 아니라 코드 유도와
`tests/world10-band-default.test.ts` 의 통합 검사**(다섯 소비처가 한 거리를 가리킨다)다.
화면으로 이 축을 가르려면 **세계 끝이 실제로 보이는 시점**(게이트 밖 긴 직선, 76.8m 너머가
프레임에 드는 자리)이 필요하고, 이 회차는 거기까지 안 갔다 — 다음 회차의 일이다.

⚠ 옛 회차가 이 캡처를 두고 *"세계 끝이 안개 없이 드러난다"* 고 적었는데, 그 화면의 밝은 띠가
**안개 부재인지 하늘 돔 하반부 채움인지 갈리지 않았다**(`decide/fog.ts` 가 「끄는 노브가 없는
후보 셋」으로 이미 적어 둔 자리다). 코드상 미추종은 확정이지만 **그 PNG 가 그것을 보여준다는
주장은 실측으로 약하다.**
