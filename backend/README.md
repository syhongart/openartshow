# backend

서버 코드 자리. **아직 비어 있다.**

## 지금 상태

OpenArtShow는 현재 **백엔드가 0인 정적 서비스**다.

- 호스팅: GitHub Pages (`deploy.yml` → `gh-pages`)
- 저장: 전부 브라우저 `localStorage` (아바타·공간·방명록)
- 멀티플레이어: P2P(peerjs 공용 브로커). 우리 서버를 거치지 않는다
- 작품 이미지: 사용자 기기에서 인코딩해 로컬 저장. 업로드 없음

그래서 이 디렉터리는 지금 **자리만 잡아 둔 것**이다. 서버가 필요해지기 전에 위치를
정해 두는 편이, 필요해진 순간에 급하게 정하는 것보다 낫다.

## 여기 들어올 것 (예정)

서버가 실제로 필요해지는 지점은 세 갈래로 보인다.

| 갈래 | 왜 서버가 필요한가 |
|---|---|
| 회원·인증 | 기기가 바뀌어도 내 전시가 남으려면 |
| 공간·작품 저장 | localStorage는 용량 한계·기기 종속·초기화 위험 |
| 갤러리 색인 | "남의 전시 둘러보기"는 클라이언트끼리 알 수 없다 |

P2P 시그널링도 후보지만, 공용 브로커로 돌아가는 동안은 우선순위가 낮다.

## 규약 (서버를 놓을 때)

- **프론트는 백엔드 없이도 동작해야 한다.** 지금 라이브가 그렇고, 그 성질을 잃지 않는다.
  서버가 죽어도 전시를 보는 것만은 되어야 한다.
- 자기완결 원칙(외부 호스트 0·CSP `default-src 'self'`)은 프론트의 것이다. 백엔드가
  생기면 그 origin을 CSP에 명시적으로 추가한다 — 와일드카드로 열지 않는다.
- 개인정보·결제가 얽히면 §6 법무 게이트를 먼저 통과한다.
