# 위험작업 2인 게이트 (§10-2)

대상: force-push · 삭제 · 이력 재작성 · gh-pages 강제 등 **되돌리기 힘든 작업 전부**.
원칙: 실행자(부팀장 R)와 승인자(팀장 A)를 분리한다 — §10-4.

## 절차

1. **실행 보류** — 명령을 아직 실행하지 않는다.
2. **서명 5항 작성** (실행자가 작성):
   - ① 대상 브랜치:
   - ② 백업 유무: (백업 커밋/브랜치/태그의 정확한 ref)
   - ③ 되돌리기 경로: (실패 시 복구 명령 그대로)
   - ④ 영향 파일 수: (`git diff --stat` 수치)
   - ⑤ 라이브 영향: (gh-pages/사용자 노출 여부)
3. **팀장 서명 요청** — team-lead 에이전트에 5항을 브리프로 전달 (§10-5: 결정 요청 1개 + 근거만, 원문 파일 통째 금지).
4. **승인 시** — 5항 기록을 DEVLOG에 남기고 실행. **반려 시** — 사유 반영 후 재요청 또는 철회.
5. **실행 후** — ③의 되돌리기 경로가 실제로 유효한지 1회 확인(dry-run 가능한 경우). 롤백성 작업이었다면 rollback-verify 스킬로 이어간다.

## 금지
- 백업(②) 없이 승인 요청 금지 — 자동 반려 대상
- "급해서 선실행 후보고" 금지 — 긴급대응이라도 게이트는 생략하지 않는다 (사고 근거: 롤백이 옛 파일을 되살려 보안패치 유실)
