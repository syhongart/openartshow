# 교차리뷰 · 릴리스 승인 (§10-4)

수행자: release-reviewer 에이전트 (구현자와 반드시 다른 세션).

## 절차

1. **범위 확정** — 리뷰 대상 diff를 받는다: `git diff <기준>..HEAD --stat` 후 파일별 diff. 구현자의 자기평가는 참고만, 판정 근거로 쓰지 않는다.
2. **회귀 중심 리뷰** (과거 사고 패턴 우선):
   - 배포 매니페스트: deploy.yml `_site` 조립에서 빠지는 신규 파일 없는가 (guide.html 404 사고 패턴)
   - 보안 퇴행: CSP 메타·safeMediaUrl·P2P 검증(64KB/30건/s/좌표 클램프) 약화 여부
   - 삭제된 코드: 의도된 삭제인지, 롤백/병합이 되살린 옛 코드는 없는지
3. **스모크 위임** — executor에 smoke-check 스킬 실행을 발주하고 6항 결과를 받는다. 검수관이 직접 스모크하지 않는다.
4. **판정**:
   - `승인` — 지적 0 + 스모크 6/6
   - `조건부 승인` — 권고 지적만 존재 (조건 명기, 배포 가능)
   - `반려` — 블로커 지적 또는 스모크 FAIL (파일:라인 + 사유)
5. **기록** — 판정과 블로커 목록을 부팀장에게 반환. 부팀장이 DEVLOG에 릴리스 기록과 함께 남긴다.

## 금지
- 검수관이 코드를 직접 고치는 것 (§10-3 위반)
- 구현자가 자기 변경을 셀프 승인하는 것 — 이 스킬의 존재 이유
