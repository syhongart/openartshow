강점과 값

모든 선택에는 값이 따릅니다. 좋은 점만 적으면 다음 사람이 무엇을 조심해야 하는지 모릅니다.

강점

  • 외부 호스트 0 — 자기완결 CDN·웹폰트·원격 이미지를 하나도 안 쓴다. 남의 서버가 죽어도 이 사이트는 산다. 스모크가 10개 페이지에서 외부 호스트 요청 0을 매번 확인한다. 대가는 아래 「값」에 적었다 — 벤더 59,583줄이 저장소 안에 있다.
  • 규율이 문서가 아니라 게이트다 린트·타입·참조무결성·테스트가 npm run gate 한 번으로 돌고, 통과 스탬프가 커밋 훅에서 대조된다 — 게이트를 안 돌리거나 돌린 뒤 파일을 고치면 커밋 자체가 막힌다. 손으로 조립하던 때 같은 실패를 두 번 하고 구조로 옮겼다.
  • 분해해도 부르는 쪽이 안 깨진다 파일을 쪼갤 때 원래 이름을 얇은 재수출 배럴로 남긴다 (space-render.js·ui.js·chibi.js). 내부는 자유롭게 재배치하고 소비자의 import 경로는 그대로다.
  • 서버에 저장하지 않는다 — 파라미터가 곧 공간 전시 공간과 아바타는 JSON 스키마로 표현되어 링크·localStorage 에만 담긴다. 렌더는 기기에서 파생된다. 계정 서버도, 유출될 DB 도 없다.
  • 안전망이 두껍다 — 테스트 30,549줄 구현 대비 22.6% 다. 다만 통과가 검출력의 증거는 아니다 — 결함을 고치면 그 결함을 일부러 되살려 테스트가 실제로 깨지는지(뮤테이션) 확인한다. 안 깨지면 게이트가 아니라 장식이다.

치르는 값

  • 같은 로직을 .ts 와 .js 두 벌로 들고 있다 GitHub Pages 정적 직서빙과 vite 빌드를 동시에 만족시키려는 대가다. .ts 가 진실이고 .js 는 산출인데, 재생성을 빠뜨리면 라이브가 옛 로직을 계속 서빙한다. 지금은 사람이 지키는 규율이고 게이트가 아니다.
  • 오픈월드가 두 벌이다 — world1 2,372줄 + world2 18,656줄 현행(world.js)과 재작성(world2/)이 병존한다. 교체 전까지 고칠 것이 생기면 두 곳을 보거나, 한쪽을 포기해야 한다. 실제로 오늘도 하늘 코드를 양쪽이 공유하는 구조 때문에 라이브 무영향 확인이 따로 필요했다.
  • 헤드리스 검증이 감독 실기기를 재현하지 못한다 자동 검증은 WebGL(swiftshader)로 돌고 감독 기기는 WebGPU다 — 렌더 경로가 다르다. 2026-08-06 별 크기 건이 정확히 여기 막혔다: 세 값을 렌더했는데 화면이 구별되지 않았고, 원인은 헤드리스에 그 별이 아예 안 뜨는 것이었다. 이 사각은 열려 있다. 시각 판정은 감독 눈이 유일한 수단이다.
  • 성능 게이트가 아직 아무것도 막지 않는다 개수 불변식과 하늘 예열은 CI 에서 관측만 한다(종료 코드에서 빠진다) — 러너 성능 편차의 거짓 실패 위험을 아직 안 재봤기 때문이다. 관측은 면제가 아니라 데이터 수집이고, 승격 없이 남으면 그때부터 장식이다.
  • 큰 파일이 남아 있다 아래 상위 목록이 그것이다. 다만 줄 수는 분해 기준이 아니다 — 진입점은 "조립" 이 책임이라 큰 것이 자연스럽다. 기준은 책임의 혼재이고, 그 판정 기준을 세우는 일은 아직 열려 있다.

큰 코드 파일 10개

깨지 않는 네 가지

1

보호 파일(라이브 미술관 4개)을 새 기능이 역참조하지 않는다. 신규는 독립 가산 모듈로 짓는다.

2

모듈 그래프에 순환 의존이 없다.

3

공간·아바타 데이터는 예외 없이 정규화 함수(SSOT)를 지나서만 렌더·저장으로 흐른다.

4

보호 파일 수정은 사전 서명 대상이다 — 라이브 무중단이 우선한다.
